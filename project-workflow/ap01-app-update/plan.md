# AP01 独立 App 更新计划

更新：2026-11-03。D1 非实机纵向链路已验收；已修改平台/App 代码，未部署。

权威方案：[设计](../../docs/ap01-app-update-design.md)。复用现有多 App screen_host，改为开机加载完整 App 集合、版本化直接 C 函数表、提交后重启切换；单个和批量更新共享同一集合事务，整批成功或回退。不再推进在线热卸载。

## 顺序与交付

| 阶段 | 交付与完成证据 |
| --- | --- |
| D0 文档收敛 | 设计、任务、状态及旧规范边界一致；只表示方案已整理 |
| D1 真实 App 纵向链路 | 冻结 C API/入口/包 ABI；真实 codex_status 最终链接零未解析导入、双基址规范化、APX2；在模型开机加载并注册现有宿主，明确替身调用边界 |
| D2 多 App 开机平台 | 唯一常驻维护/界面宿主，Manifest 有界加载、身份/资源隔离、独立健康监督；真实业务包加第二个独立测试包，预算和冲突验证 |
| D3 集合更新与恢复 | 版本化 Manifest/日志/每包续传；SwitchPending 后重启、启动前持久消耗机会、整集提交/回退、清理及持久边界故障测试 |
| D4 产品链路 | 生产 handler 绑定、OTA/Bundle/Wi-Fi 协调、CLI/Bridge 单更/批更/重连；真实包端到端安装与回退、跨仓回归 |
| H 实机准入（排除） | 可执行内存/cache、断电与看门狗、首次迁移和救援；须另行授权 |

每阶段优先连接实际路径，不用未被生产调用的模块构建成功代替完成。D1 可先接固定测试启动清单，D2 再替换为已校验 Manifest；不能重新引入精确 ROM 地址到 App。

旧实现按用途迁移：APX2/摘要/故障经验、事务幂等与下载机制复用；单包日志/HTTP 字段版本升级；卸载门与报文服务在替代路径验证后再删除。保留正常 UI 销毁、线程安全、写入一致性和维护资源保护。

非实机实现范围继续包括 App 与 Bridge/CLI 离线适配，本轮先恢复 D1 执行。QEMU 必须在 james.local 的 Docker 中运行，不向宿主安装依赖。实机准入未通过不阻止授权的离线工作，但所有候选保持不可部署。

历史构建/实验：[构建](s1-build.md)、[最小加载](s1-load-probe.md)、[Docker QEMU](s1-qemu-james.md)。它们证明旧实现的局部性质，不是新多 App 重启方案验收。
