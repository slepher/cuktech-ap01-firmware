# App 独立存储空间校验（2026-11-05）

结论：App 包已独立于 ROM，当前位于 `/resource/app-store`，但与业务文件共享 Res 文件系统。当前 16 MiB Flash 没有未分配区域；不能直接将 App 改到一个空闲分区。初次分区校验仅进行只读操作；后续预算调整与安装结果见文末。

## 实机证据

通过设备码认证，只读取物理地址 0xe000 和 0xf000 各 512 字节。两次 boot_id 均为 142733745704953541；传输 CRC、分区头 CRC 和条目 CRC 均通过。两表 age 为 48/49，最新表 FW active=1。原始证据与解析结果位于 `build/storage-check-20261105/`。这不是完整 Flash 导出。

| 区域 | 物理范围（不含末地址） | 容量 | 是否可直接存 App |
|---|---|---:|---|
| Boot2、双分区表 | 0x000000–0x010000 | 64 KiB | 否，启动区 |
| FW 槽 0 | 0x010000–0x710000 | 7 MiB | 否，现有 0031 救援 |
| Data | 0x710000–0x720000 | 64 KiB | 太小，且含现有配置 |
| Crash | 0x720000–0x72c000 | 48 KiB | 太小，已有用途 |
| bt | 0x72c000–0x730000 | 16 KiB | 太小，已有用途 |
| Ota | 0x730000–0x7b0000 | 512 KiB | 原厂升级使用，不能视为空闲 |
| FW 槽 1 | 0x7b0000–0xeb0000 | 7 MiB | 否，当前 0041 平台 |
| Res | 0xeb0000–0xff0000 | 1.25 MiB | 当前 `/resource`，包与业务数据共享 |
| Reserve | 0xff0000–0x1000000 | 64 KiB | 太小，尚未证明可回收 |

`mfg` 条目为 0x7b0000 起 3 MiB，与 FW 槽 1 重叠，并不是额外容量。ROM 尾部未占满其槽位也不能自动转为持久 App 空间：仍在固件升级分区范围内。

## 原厂 0041 静态核对

使用固定原件 `roms/0041/ap01-1.0.2_0041.bin` 本地反汇编，证据位于上述目录的 `code.disasm`：

- 0xa0059a6a–0xa0059a98：注册从 0x730000 起、长度 0x80000 的 `/dev/ota`。
- 0xa00b503e 函数在 0xa00b5084/5088 打开 `/dev/ota`，随后 fstat 校验容量；关联日志标签为 `arch_ota`，包含升级大小超过分区的错误。存在实际调用，不能因目前无升级任务就认定可永久挪用。具体哪些升级形式使用该暂存仍需进一步审计。
- 0xa0059afa–0xa0059b4a：注册从 0xeb0000 起、长度 0x140000 的 `/dev/resource`，挂载 LittleFS 到 `/resource`。
- 0xa0055c8c–0xa0055caa：`/dev/data` 挂载为独立 `/data`，不是 `/resource` 的另一名称，但分区容量仅 64 KiB。
- 分区设备注册使用硬编码地址/大小；仅修改分区表不足以安全重分区，还需同步原厂驱动和升级路径。以上为原件静态证据，不声称已实测重分区或新挂载。

## 原 1 MiB 预留为什么失败

`ap01PlanSetBeginV3` 对本次首装要求：

- 新 App：205360 B。
- 四份最大 Manifest 预算及两份日志：4 × 3584 + 2 × 320 = 14976 B。
- 维护预留：1048576 B（1 MiB）。

合计 1268912 B。相对 1310720 B 的 Res 分区，只剩 41808 B 可容纳原有文件及文件系统占用。实际安装拒绝与此预算相符，但现有诊断接口未提供具体已用/可用字节数，不能据此声称整个分区已经写满。

更关键的是，旧包和同尺寸新包并存时，包 + 元数据预算 + 预留至少为 1474272 B，已经超过整个 Res 分区，尚未计业务数据。这证明固定 1 MiB 预留不适合当前包的后续更新容量，必须重新核定；不应通过清理用户数据来掩盖预算冲突。

## 可行方向与边界

1. 优先复用现有 Res：保留 `/resource/app-store` 与业务目录的逻辑隔离，先取得真实 total/used，核定原厂文件、业务增长、旧/新包并存、LittleFS 写放大和掉电恢复所需余量，再调整预留。初次校验阶段未降低预算或删除文件；后续授权调整见下节。
2. 若必须有物理独立 App 分区，512 KiB Ota 只能作为待改造候选：需先消除/迁移所有原厂使用者并验证内置升级及救援兼容，再接入独立存储后端。当前包两份共 410720 B，扣上述元数据预算后只余 98592 B，且未扣新文件系统及其他开销，容量增长空间有限。不能直接格式化使用。
3. 扩大物理空间需要整体重分区或缩小 ROM 槽；现有 ROM 约 6.61 MiB，且要保留 0031，不属于一次路径配置变更，不建议作为当前首装解阻方案。
