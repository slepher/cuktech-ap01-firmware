# 0031 独立 OTA 端口：原厂符号绑定清单（2026-10-17，进行中）

0031 只读原件 `ap01-1.0.2_0031.bin`（6,804,520 B，SHA256 `8a721fc8…5c1cb`）的 RV32 裸 BIN 分析，目的：把 `firmware/ap01/ota_0041.c` 使用的 18 个原厂调用点移植到 0031。映射：file offset 0 → base `0x9ffff000`、entry `0xa0000000`（file offset 0x1000），REA 6.5.0 + Ghidra 12.1.4，`RISCV:LE:32:default`/gcc。证据导出 `artifacts/ap01-research/qemu-0031-20261017/rea-0031-p0-bundle.json`。

## 方法（两种独立路径交叉）

1. **REA 反编译/调用图**：对候选地址取 `procedure_info`/`procedure_pseudo_code`/`procedure_callees`，按 NuttX 语义与 errno 处理识别。
2. **0041 函数字节签名**：0041 与本版同产品线；取 [ota_0041.c](../../../firmware/ap01/ota_0041.c) 中每个 0041 绑定地址在 0041 原件（`artifacts/ap01-research/ap01-1.0.2_0041.bin`）文件偏移处的函数前缀字节，在 0031 原件中做精确/短前缀搜索，得到候选后用路径 1 复核。脚本为一次性本地工具（未入库），结果表见下。

`VA = 0x9ffff000 + file_offset`。所有地址均为运行虚拟地址，不是烧录偏移。

## ABI 核对项（与 0041 逐项比对）

- `poll_fd` 24 B（fd/events/revents/priv[3]）：0031 `poll` 内部按 `piVar3 + 6` 递进（6 字 = 24 B），一致。
- `ip_addr` 16 B（family/port/addr/pad[8]）：bind 伪代码只传指针，结构布局需在移植时按 0031 伪代码再核。
- errno 约定：socket/bind/poll/accept/sendto/setsockopt 均在错误路径调用 `0xa00266c0` 并写入正值错误码、返回 -1，与 0041 一致。
- float ABI / gp / 小数据段：0031 为 `ilp32`（未见浮点参数），0041 使用 `ilp32f`；模块不得使用浮点参数，避免 ABI 差异。
- 栈预算：各原厂函数栈帧需在移植时取 prologue（`addi sp,sp,-N`）实测记录，不沿用 0041 数值。

## 未决/风险

- 以上签名匹配证明“同源代码在 0031 的位置”，不等于原厂 ABI 完整等价；移植前仍需按 `ota_0041.c` 调用形态逐项核对参数个数/顺序/返回值。
- 0031 的 `boardctl` 与 0041 的 `0xa0055a14` 不是同一地址；0041 的 `0xff13` 提交返回 0 的语义在 0031 需以 `0xa005576c` 的 `0xff13` 分支复核（含 `ro.boot.update_slot` 与 boot image 序列表）。
- 0031 的 Flash 写入/首字节恢复/CRC 函数尚未确认，不能开始候选构建。
