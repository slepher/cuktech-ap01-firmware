## 真正新增：正常算术、ABI 与寄存器字段

### 频率变化时的分频/周期

`a01367c4` 比较刚重读的缓存频率与调用开始时保存的旧频率。相同则跳过频率计算、停机请求和周期寄存器写入，只按缓存周期更新两路阈值；不同才进入 `a013680e`。

ROM `a061b5a8..a061b5af` 原字节 `00000000d0129341` 是 binary64 `80000000.0`，低/高 word 分别载入 s6/s7。`s2=freq`、`s3=1`、`s8=65536`。三条直接调用按 AUIPC 所在 PC 独立解出，不能用第二条 JALR 的 PC 计算：

| 调用点 | 目标 / 实参 ABI | 正常语义及依据 |
| --- | --- | --- |
| `a0136822/6826` | `a001fa84`；a0=s2；返回 a0=低32、a1=高32 | 无符号 u32→binary64。入口保存 a0、对非零值调用 `a001f202` 前导零 helper，再由 `0x41e-CLZ` 构造指数；没有将 bit31 当负号的分支。CLZ 的256项 byte表逐项等于输入索引 bit_length，原字节静态检查通过 |
| `a0136832/6836` | `a001d7fc`；a1:a0=80MHz常量，a3:a2=上一返回；返回 a1:a0 | binary64 除法。正常有限非零路径拆两数11位指数、补隐藏位，指数相减（`d90a`）、符号异或（`d912`），进入 `d9ca`，以 `divu/remu` 分段求商；最终按当前 `frm` 舍入并重组 binary64 返回 |
| `a013683a/683e` | `a001f042`；a1:a0=商；返回 a0 | binary64→无符号 u32，正常正有限数截掉小数。读取指数/符号后以 `0x433-exp` / `0x413-exp` 的逻辑移位组合整数；被丢位非零可置 fflags，**没有按 frm 给整数加一** |

不是 fa 寄存器传参，也不以通用反编译的 `undefined()` 签名代替此调用 ABI。对 helper 的上述数学职责属于有原指令支持的分析推断；并未认证为某一版本 libgcc/newlib 或排除为整库。除法读取当前 `frm`，因此用 `div64_frm` 表示，不擅自固定为 round-to-nearest。其普通正有限路径足够解释本 PWM 合同，NaN/Inf/负数等不在本题验证范围。

调用后 `s4=a0`。若 `s4<65536`（无符号比较）就选定当前分频；否则分频 s3 加1，分母 s2 以32位加法加原频率，再循环，直到 s3==65536。原循环穷尽分支将 s3减1、s4=s3，即两个值均65535；这只是保留原分支，不作异常输入试验。没有把乘加改成64位或把分母改成另一次独立除法。

因此正常成功选定路径为：

```c
// 分析伪代码，不是原源码；u32wrap 保留寄存器宽度。
denominator = frequency;       // uint32_t，s2
divider = 1;                  // s3
do {
    denominator64 = u32_to_binary64(denominator); // a001fa84
    quotient64 = div64_frm(80000000.0, denominator64); // a001d7fc
    period32 = truncate_positive_binary64_to_u32(quotient64); // a001f042
    if (period32 < 65536u) break;
    ++divider;
    denominator = u32wrap(denominator + frequency);
} while (divider != 65536u);
if (divider == 65536u) { --divider; period32 = divider; }
lower->period16 = (uint16_t)period32; // a013685c，先于MMIO等待
```

随后才请求停止并使用旧轮询合同。满足原停止状态条件的路径在 `a01368a8..68cc` 写：

```c
base[0x40/4] = (base[0x40/4] & 0x3fff0000u) | divider | 0x40000000u;
base[0x48/4] = (base[0x48/4] & 0xffff0000u) | period32;
```

频率寄存器低16位写入**divider本身**，没有减1；bits31:30置为01。原停止等待提前结束的分支跳到 `a01368d0`，会跳过这两次 MMIO 写，但仍继续阈值与 enable 更新；缓存周期已先写。不能把“返回0”写成寄存器配置必已成功。

### 两路 duty→对称阈值

两分支都逐次从 lower `+8` 重载表指针、从 `+0xc` 以 lhu 重载周期，表项步长8，两个 duty 均按32位读取；当前通道号用 lrbu。记 `P=load_u16(lower+0xc)`、`D=load_u32(entry+4)`：

```c
half = P >> 1;                             // 无符号逻辑右移
delta = u32wrap(0x8000u + u32wrap(P * D)) >> 17;
high = u32wrap(half + delta);
low  = u32wrap(half - delta);
packed = ((high & 0xffffu) << 16) | (low & 0xffffu);
write32(base + 0x50 + 4 * channel, packed);
```

`D` 不是已截为16位的参数，乘积也没有提升为64位。`0x8000` 在右移17位前加入，不能改写为通常的 `+0x10000` 四舍五入；周期先 `>>1`，奇数低位在阈值居中前丢弃。两个端点都由打包截为16位，不饱和；本文不探测越界 duty 行为。正常 `D=0` 时两个端点相同，不能从该静态事实推出硬件电平。

固定通道2/3对应阈值地址 `0x2000a458/0x2000a45c`。频率变化路径每写一路阈值后，重新读取通道 byte，读改写 `base+0x44`，置 bit `(channel<<2)`，即8/12；相同频率路径没有这两次 enable 位写入。两路都写完后两分支汇合到 `a013692c`，清 `base+0x40` 的 bit27（`lui 0xf8000; addi -1` 得 mask=`0xf7ffffff`），再沿旧启动轮询返回0。
