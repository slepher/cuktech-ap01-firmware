# 0041 第二应用共存与窗口热重建

日期：2026-10-20。承接[首轮重构](screen-host-refactor-20261020.md)。本次继续修改两个仓库并执行离线验证；不访问设备、不刷机、不部署Bridge。

## 实现修复

1. 原挂钩每次创建Runtime并启动三条服务线程；窗口删除后再次挂钩会重复启动。现在通过0041原生LVGL定时器链表查找本宿主保留的定时器/context，重建只绑定新窗口，复用原Runtime、业务、维护和发现执行器。重复挂钩同一窗口直接返回。没有新增可写全局或借用未经验证的RAM槽。
2. 窗口删除先设置不可用并递增UI epoch，再取消宿主事务、退役所有应用图像、清空待提交/激活队列，解除窗口引用。定时器保留为生命周期锚点；窗口缺席期间UI业务不访问旧对象，独立维护和发现继续运行。
3. 业务操作在开始时捕获epoch，帧也携带epoch。跨窗口的迟到帧被拒绝；切换token和每应用revision在重建中保持连续，旧窗口请求不能因编号复位重新有效。重绑后在既有业务线程重绘当前context，必须重新收到真实draw。
4. 启动完成与窗口可用状态分开。即使初始化期间窗口已经退役，业务/维护线程也不会因旧ready CAS失败而被跳过。
5. 原对象删除绑定 `0xa00d7806` 仅递归执行class析构，不发送DELETE、不摘链、不释放对象；已改为完整公共入口 `0xa00ded6c`。这同时修复图像退役、页面池撤销与窗口删除。[原件函数证据](../../analysis/screen-host-delete-abi-20261020.json)。
6. 完整删除暴露原厂Power1等页面对尚未创建的可选定时器调用 `lv_timer_delete(NULL)`。平台新增空指针保护：VA `0xa008ae58` 的8字节入口跳到只读XIP函数，NULL直接返回，非NULL重放原8字节前导并执行未修改的 `0xa008ae60` 尾部。未跳过页面清理、未创建假定时器。打包器核对原件前导并逐字节重建；允许修改范围变为UI挂钩8B、定时器保护8B、无签名OTA分支2B，其余原件资源保持不变；原40B恢复尾记录按新长度/CRC更新并移动到镜像新尾。
7. 原厂四类通知注册只按函数去重，不刷新旧context。DELETE期间按函数和窗口双重匹配，解除并释放本窗口订阅；新窗口由原件构造器重新注册。测试逐轮核对旧窗口订阅从4变0、新窗口为4，防止旧指针残留，也不删除其他窗口的订阅。

平台的查找/detach操作只能在UI线程调用。保留的50ms定时器在窗口缺席时只执行受ready保护的轮询；它不代表窗口已可用，boot health仍检查ready。

## 验证装配

`check-ap01-native.py --screen-host-probe` 才加入独立第二应用 `host_probe` 与UI线程探针入口。它有两个稳定ID、两个独占root、自己的I4图像和poll/input/draw/unbind回调，不调用codex_status的Bundle或渲染业务。普通构建不包含该应用与探针入口。

最大组合为原厂九页、codex_status八个root、第二应用两个root，共19个实际LVGL页面；第二应用物理child为17、18。逻辑重排保持物理绑定，隐藏poll与输入锁独立；系统遮挡时应用隐藏自有图像，保留宿主/配对覆盖层。

窗口重建探针在原UI线程删除真实主窗口，随后重放原件内联的完整九页构造代码：入口 `0xa005cd68`，成功出口 `0xa005d1a0`，失败出口 `0xa005cdc2`。只准备该段需要的1024字节栈局部及已核对的s0/s1/s2；不重放LVGL、fbdev、输入设备初始化或UI主循环。原代码执行已有挂钩，因此测试包含真正的Runtime查找和重新装配，不直接替换一个测试用新Runtime。
