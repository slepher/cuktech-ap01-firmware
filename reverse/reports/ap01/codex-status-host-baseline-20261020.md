## 2. 源码显示的实际 UI 接入方式

- `ports/ap01/native_0041.cpp` 的 `ap01Register0041` 包装原厂 `0xa00afc88` 按键回调，创建长期 `Runtime`、50 ms UI 定时器及业务启动线程。运行状态在堆上，不依赖可写静态段。
- `Runtime::panel` 仅接纳原厂页面 `0..8`，把普通面板放在这些页面内部。注释明确指出原厂屏幕级遍历按自定义窗口布局读取 `+0x3c kind`，因此保留顶层9个子窗口。`ensureContent` 按承载页面调整单个内容面板，并非每个模板一个顶层窗口。
- 模板是应用内部的虚拟页面。`Runtime::key` 以进入 Pet 的原厂有向边及其反向边插入模板组，调用原厂处理前后比较页面，并保留配网门控路径；不按页号增减推断环回。
- 当前实际插入判断是正向 `after == 7`、反向 `before == 7`，与新设计指定的 **Pet之后、Settings之前** 不同。改位置属于显式行为变更，不能称现有代码已满足新方案。
- 内部模板切换使用 `activate(next)`；进入/退出虚拟页面结合 `ensureContent` 和原厂滑动器。不能把已有边界动画证据扩展为“任意相邻模板均有独立 root 的双屏动画”。
- `tick` 处理帧发布、旧 Bundle 退役、自动恢复意图、配对/维护优先级及可见性；真实输入会取消待恢复意图。`focused` 表示虚拟模板页当前占有显示，并不等于新设计中的 `FOCUS_LOCKED` 输入锁。

## 3. 已有构建链可以复用的部分

`tools/build-ap01-rom.py` 从固定 SHA256 的原厂0041重建镜像：载荷文件偏移 `0x675000`，链接 VA `0xa0674000`，8字节 UI 调用点位于文件偏移 `0x5e180`；另有2字节 unsigned OTA 分支补丁。构建器保留原厂五个 Pet GIF、ROMFS/rcS及声明范围之外的原始字节，迁移最终恢复记录并重算长度/CRC，检查7 MiB槽容量。

`ports/ap01/native_0041.ld` 拒绝可写静态段、TLS和隐式构造器。构建/验证入口已有 `link-ap01-native.py`、`check-ap01-native.py`、`accept-ap01-rom.py`、`test-ap01-native-app.py`、`run-ap01-native-qemu.py`、`test-ap01-native-render.py`。

因此，“没有保留 GIF 的0041载荷布局”“没有常驻 Runtime/维护服务”“没有完整候选验证链”只适用于本研究仓库自身，不能作为跨仓库重构的起点。应先核对并提取现有链路，避免重新实现；也不能把提取后的新候选标成已继承34的实机验收。

34 专项记录的 Runtime 为2088 B、Business1776 B（已内嵌，不重复相加），I4帧38400 B、LVGL图像38464 B。现有实现没有逐模板帧缓存；新模型的每屏常驻 root 不应默认引入每屏完整帧副本，需单独测量对象与资源增量。这些数字是该版本记录，非重构后的预算。

## 4. 对宿主重构计划的调整

1. **先提取再替换**：从现有 Runtime 中辨认原厂绑定、生命周期、线程/服务与业务渲染边界；UI线程入口、堆状态、槽尾构建及保护范围优先复用。是否迁移维护模块须明确所有权，防止出现两个18080监听器或两个升级执行器。
2. **顶层窗口合法性已完成机制级核对**：原厂页面本身是普通对象；先前把屏幕层窗口约束推广到win子页的推断不成立。9/10/17孩子的滑动及查找原件执行通过；真实对象分配、绘制及完整事件路径仍需后续探针。
3. **保留模板层**：通用宿主的 screen 与 Bundle模板是两个层次。第一步允许一个宿主屏幕承载现有模板应用，继续由共享引擎渲染；对多模板如何参与全局导航、是否逐模板分配 slot、更新后如何保持 slot/root 稳定，先定义再实现。不要把“最多8模板”直接等同于“宿主最多8屏”。
4. **目标位置单独验收**：从当前 Pet 进入边迁到 Pet ↔ 外部屏幕 ↔ Settings 时，复验原厂条件门控、双向顺序、配网/唤醒、动画方向和连续旋转；保持33修复，禁用数字递减判环回。
5. **恢复与回执列为首批回归**：重构仍须保留原厂页不抢焦点、模板页发布自动返回、按ID恢复、删除回退、用户输入取消恢复、维护/配对优先，以及实际draw才确认当前generation。原厂动画完成与业务绘制确认分开。
6. **焦点锁是新增协议**：另实现 OVERVIEW/FOCUS_LOCKED 和3秒逃生，不能复用现有 `focused` 布尔值直接声称完成。同步回调阻塞仍受 UI线程可运行性约束。

下一步优先做现有实现与目标 ABI 的逐项映射、顶层窗口对象合法性验证及模板/宿主屏幕映射设计，然后提取可测试的共同导航核心。新多应用原型仍需独立验证；已有现场不作为实验环境随意更新。
