## 指令事实：包装参数、返回及两条分支

`a00b8bfc(a0, a1)`：a0为被委托给等待接口的指针，a1为32位值。原typedef未知。`a0561b6c` 的 ROM 字符串是 `arch_os_semaphore_get_2`，在空参数诊断构参中被引用，因此可作为包装名称识别依据；不能仅凭名称认定开源来源。

## 指令事实：一个直接调用者及 a0 来源

`a0126946` 的日志在 `a0126992..b0` 引用 `a0617798="rpc_consume_thread"`、`a025668c="rpc_agent"`。它与线程消费者形状一致，命名为有字符串依据的推断，非认证符号。输入a0保存在s4，`a0126966` 清 input+0xc 的字节。窗口中可确定的局部布局：

```c
struct ConsumerPartial { // 未知完整大小；32位指针
    uint32_t unknown_00;
    void *member_04;
    struct QueuePartial *member_08;
    uint8_t stop_byte_0c;
};
struct QueuePartial {
    uint8_t unknown_00_17[0x18];
    void *wait_member_18;
    void *other_member_1c;
};
```

- `a012698c/90` 读 input+0xc；为零跳 `a01269ea`，非零走退出局部路径。初始化为零后落入该回环检查；这只是所核窗口的控制流，未恢复所有外部写者。
- `a01269ea`：s6=load32(s4+8)。`a01269ee`：a1=1000。`a01269f2`：a0=load32(s6+0x18)。`a01269f6` 的原字 `ef2069a0` 独立重组目标为 `a00b8bfc`。
- 这三条之间无调用或厂商指令。a0的准确来源为二次成员重载，不是地址常量、不是结构体成员的地址运算 `s6+0x18`。没有空指针检查或字段写入者证据，故不能证明值必非零，也不能证明其身份等于任何全局信号量。
- 包装结果 `a01269fa` 存s5，`a01269fc` 非零跳 `a0126b10`；为零才走 `a0126a00` 起的后续操作。`a0126b10` 调 `a00b4196` 后做其他维护；局部含 `a0126b16` 直接回检查及 `a0126bb2` 回 `a0126980` 再到检查的边。这里不恢复中间RPC处理、回调或队列整体协议。

