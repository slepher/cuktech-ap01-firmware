## 自定义参数的选择与回退

```c
// a009cc0c，业务 void 视图。省略日志，不改变分支及写入顺序。
void set_custom_param_local(uint32_t input) {
    uint32_t c1 = input >> 8;       // 原指令没有先 &255
    uint32_t c2 = input & 255;
    if (!(power_index(c1) != 255 && power_index(c2) != 255 && c1+c2 < 101)) {
        log_selection_failure(c1, c2);
        if (u8_at(0x62fc9194) == 2 && c1+c2 > 125) {
            c1 = 80; c2 = 45;
        } else {
            c1 = 67; c2 = 33;
        }
    }
    uint8_t i1 = power_index(c1);
    uint8_t i2 = power_index(c2);
    // 原程序还记录输入/所选功率/映射等日志。
    uint8_t custom[4] = {3, u8_at(0x62fcb000), i1, i2};
    custom_apply_a019530a(custom);
    u16_at(0x62fc9190) = (uint16_t)input;
}
```

不符合选择条件时原程序仍继续，以固定组合发送；不是“拒绝并返回”。回退 80+45=125 的条件与普通接受条件 `<101` 不同，不能替换为统一限制。最后存储的是原输入低 16 bit，而不是所选回退组合，不做修正。此函数没有配置持久化调用、发送成功状态返回或“收到底座确认后才记值”的门控。

旧反编译还显示一条日志在局部 `custom` 字节赋值前取值。相关原始调用保留在证据中；诊断参数的 ABI/原局部变量解释未在本轮认证，不据此推导实际发送载荷。实际载荷字节以赋值和后续调用指令为准。

## 模式入口与两个 UART 载荷

```c
// a019530a；只接受第一个 byte 为 3 的输入视图。
void custom_apply_local(const uint8_t input[4]) {
    if (input[0] != 3) return;
    u8_at(0x62fcb01d) = 3;
    u8_at(0x62fcb512) = 3;
    control_change_a0195166();
    // 在同步通知之后，才读取 input[1..3] 并写全局 payload。
    u8_at(0x62fcb518) = 3;
    u8_at(0x62fcb519) = input[1];
    u8_at(0x62fcb51a) = input[2];
    u8_at(0x62fcb51b) = input[3];
    CommandView cmd = { .command=0x60, .length=4, .payload=ptr(0x62fcb518) };
    command_submit_a01951e2(&cmd);
}

// a019537a；这个 helper 自身没有 0..3 的范围检查。
void mode_apply_local(uint32_t mode) {
    u8_at(0x62fcb512) = (uint8_t)mode;
    u8_at(0x62fcb01d) = (uint8_t)mode;
    control_change_a0195166();
    if (mode == 3) {
        uint8_t custom[4] = {3, u8_at(0x62fcb000), u8_at(0x62fcb001), u8_at(0x62fcb002)};
        custom_apply_a019530a(custom); // 再次进入 control_change，未必再次通知
    } else {
        CommandView cmd = { .command=0x60, .length=1, .payload=ptr(0x62fcb01d) };
        command_submit_a01951e2(&cmd);
    }
}
```

`CommandView` 的 ABI 为 byte command@0、byte length@1、未认证 padding@2..3、32 bit payload 指针@4。半字常量 `0x0160/0x0460` 是 little-endian 的 command/length，不是两个不同命令号。**本轮确认的命令均为 `0x60`**：普通模式 payload 为 1 B 模式值，自定义模式为 `[3,参数0,索引1,索引2]`。mode==3 是“自定义”职责的高置信命名，0/1/2 的准确产品枚举名称待其他调用者/界面证据确认。

MiIO 调用者先把属性输入 1..4 转为 mode 0..3，见上轮合同；不能把调用者的检查添加到本 helper。现有首轮模型还列出普通响应处理器 `a00a8582` 和 UI 大函数 `a00f61ae` 为模式入口直接调用者；其中完整分支/生命周期尚未认证，不把前沿关系当实现已恢复。

描述符在栈上，但 `a01951e2` 不保存该指针：空闲时同步复制到活动区，忙时按已核规则同步复制到四槽待发区、去重或直接返回。1/4 B 均走复制长度范围内。提交无明确成功返回，UI 本地状态在提交前已更新；不能把此入口解释成“等待 MCU 应用成功”。传输状态、固定槽顺序、组帧 CRC/转义和部分写复用[UART 协议合同](usb-interface-ota-0041-20261023.md)，本轮不扩展缺陷调查。

## UiIFace 控制快照与同步订阅通知

`a0195166` 的 ROM 日志名为 `UiIFaceMngCtrlChange`，源码路径指向 `PogoPinMng/UiIFaceMng.c`。它只同步本地控制快照的两个字段：

```c
// 只表示已核最小前缀，不能将 14 B 当整个对象大小。
struct ControlSnapshotView {
    uint8_t unknown00[7];
    uint8_t byte07;
    uint8_t byte08;
    uint8_t unknown09[3];
    uint16_t change_mask_at_12;
};

void control_change_local(void) {
    ControlSnapshotView *s = ptr_at(0x62fcb2cc);
    if (s == NULL) return;
    uint16_t mask = 0;
    if (s->byte07 != u8_at(0x62fcb514)) {
        s->byte07 = u8_at(0x62fcb514);
        mask = 2;
    }
    if (s->byte08 != u8_at(0x62fcb512)) {
        s->byte08 = u8_at(0x62fcb512);
        mask |= 4;
    }
    if (mask == 0) return;
    s->change_mask_at_12 = mask;  // 直接覆盖 halfword，不与旧 mask 合并
    log_total_update();
    dispatch_control_a00a536c();
}
```

字段 `+7` 的比较使用双方 signed byte load，但这里进行相等判断；`+8` 使用 unsigned byte load。本轮没有给 `+7` 赋造产品含义。仅两个字段变化会由本 helper 触发通知，mask 分别是 bit1/bit2；重复调用时若值未再变化就直接返回。因此 mode==3 的两次 control_change 调用不自动等于两次通知。

dispatcher `a00a536c..a00a53bf`：初始全局快照指针为 0 时返回；从 `*(head+4)` 取首节点，对非空 callback 调用 `callback(node_userdata, current_snapshot_pointer)`，每次调用前重新从 `62fcb2cc` 取快照指针。节点 callback@0、userdata@4；下一节点按 `*(node + *(u32*)head + 4)` 读取。头部首 word 在这里作为链字段偏移使用，完整注册器/对象布局尚未恢复，不把它猜成固定数字。

遍历结束后，原指令对当前全局快照 `+12` 的 halfword 清零。通知携带借用指针，没有本地快照复制或 free；消费方在同步调用期间能看到变化掩码，不能擅自将 dispatcher 改成异步投递或永久保留 mask。分发代码没有认证消费者可长期持有该指针，也未恢复回调增删节点的完整合同。
