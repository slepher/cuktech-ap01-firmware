核心最小语义伪代码（分析命名，并非原始源码）与 A01 一致：

```c
// worker内已有提示音体此处不重复恢复。
while (running) {
    int r = wait_wrapper(request_sem);
    uint8_t fresh_running = running;
    if (r != 0) { if (fresh_running) log_wait_failure(); continue; }
    if (!fresh_running) break;
    existing_inline_beep_body();
}
post(exit_sem);
return 0;
```

上式只表达轮询与退出合同；顶部每次重新读 volatile 语义字节，不将 C 的未声明变量当原程序类型证据。`62fc9288` 状态块字段事实仍为 request `+0x10`、exit `+0x1c`、token输出 `+0x28`、running byte `+0x2c`；信号量内部结构及 token typedef 未核。
