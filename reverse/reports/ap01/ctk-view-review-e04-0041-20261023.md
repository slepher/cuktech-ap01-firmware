# 0041 E04：CTK callback、栈视图及主要消费独立复核

E03 的 **注册→间接 callback→port1 转换→标签/四槽/SOC 消费→回调栈归还** 局部闭包限定通过。九个合同的地址、参数及主要控制流均与原字节相符；需要收紧一处“port2 复用”的描述：两个端口分支使用相同的栈地址和布局，但成功执行 port1 分支后，本次调用不会再执行 port2 转换。两分支的端口谓词互斥，不能把同一局部槽的静态复用画成同次通知中的连续两次转换。

这是新 agent 的独立静态技术复核，工作树 `re0041-e04`、分支 `codex/re-0041-e04`，基线 `85c61e2dfa2a2326e1698b9b24766d937632321f`。只写本报告和独占 analysis 目录，未修改 E03。未执行固件、项目构建、历史回放、异常输入或缺陷验证，未连接设备/外部服务，未修改 ROM、生产代码、处理器模型或共享 REA 状态。

## view布局、门控与一个纠正

view在 `[s0-0x94,s0-0x42)`，共0x52 B；保存寄存器最低位置是s0-34，视图位于0x100 B frame中且不相交。`a00aef4a..58` 以fill(dst,0,0x52)建立零初始化视图。端口来自item+24的bits5..4及低nibble，extu原字 `a00adbc4:0bb74714` 确为msb5/lsb4。高位0且低位0/1/2映射port1/2/3，高位1/2映射4/5；其他分支不扩认证。

| view偏移 | 本轮读取/接口含义 |
| --- | --- |
| +00 / +01..06 | u8原port / 数量与总数；总数读取+6 |
| +08/+0a/+0c/+0e | u16 SOC整数/小数/小时/分钟 |
| +10+16*j，j=0..3 | 16 B row：u8 active/direction，u16功率、电压整数/小数、电流整数/小数 |
| row+0c/+0d/+0e | u8 kind/ordinal/行有效 |
| +50 | u8 SOC小数显示模式 |

panel+20+32*j是四个slot；slot+4名称、+8方向、+c功率、+10单位、+14电压、+18电流、+1c特殊图标。panel+4/+8/+c为SOC widget/标签/单位，+10/+14/+18/+1c为时间控件。这些是局部字段视图，不认证整个panel结构或构造所有权。

port1要求 `load8(62fc4062)==1 && s3==1`。converter返回0在 `a00aef66:6304051c` 跳 `a00af12e`，不消费该视图。非零后state为 `load8(62fc4067+index)`；state1先名称并置2，state0跳过，state>1由 `a00af12a` 的unsigned比较进入值更新。标签循环先增i，地址严格为kind=`dst+12+16*i`、ordinal=`dst+13+16*i`、slot=`panel+32*i`，i=1..u8总数；不是dst起始连续数组，也不是从row0 metadata再额外偏移一行。a3总数由循环条件加载后直接保活到call，复核伪代码使用变量表示这个读取，不能人为多加一次原程序load。

**纠正 E03 的“下一分支可能重新填充同一槽”表述：** `a00af12e` 的port2路径要求global开关为1，且 `a00af13a` 要求s3==2。在成功port1名称/四槽/SOC路径，s3保持1，call只按保存寄存器ABI暂借它，故port2谓词失败。本轮未发现核心行为错误，纠正的是两分支静态共享槽与同次执行复用的区别。port2实际执行时仍确实在 `af16a` 用s0-94清0x52 B，以a1=2转换，`af180` 返回0跳公共结尾；不能说每次port1执行之后都会再清零。最终 `af250..25e` 检查/清app+54后到 `adb20`，恢复寄存器、sp+=100并返回。

以下仅为已核正常port1的顺序视图，不是原源码或完整回调；`bit_from_item_then_app` 表示每次先读item.mask，未满足才读app+54，不能缓存到循环外。

```c
view = entry_sp - 0x94;
if (port1_enabled == 1 && port == 1) {
    panel = load32(load32(child(app,1)+0x10)+4);
    fill(view,0,0x52);
    if (convert(view,1) != 0) {
        state = load8(state_base+index);
        if (state == 1) {
            i = 0;
            while (i < (total = load8(view+6))) {
                ++i;
                name(panel+32*i,load8(view+12+16*i),
                     load8(view+13+16*i),total);
                i &= 0xff;
            }
            store8(state_base+index,2);
        } else if (state < 2) goto consider_port2;
        for (j=0; j!=4; ++j) {
            row=view+16+16*j; slot=panel+32+32*j;
            if (load8(row+14)!=0) {
                log_row(j);
                if (bit_from_item_then_app(0x20000)) {
                    status(slot,load8(row));
                    values(slot,row);
                }
            }
        }
        if (bit_from_item_then_app(0x8000)) battery(panel,view);
    }
}
consider_port2:
// port2有自己的port==2门，和上述port1执行互斥；使用同一view地址。
// 公共结尾清pending mask，恢复本次frame，view失效。
```

第三调用点 `a00ae238` 必须保留不同合同：先fill0x52，以port1转换，紧接 `ae23c/240` 重置a1=view/a0=panel，`ae242` 调 `a00ef1d4`，`ae24c` 调 `a00ef2da`，中间没有converter返回判断。因此“返回0跳消费”只认证在线port1/port2主分支。offline/状态变化路径可能消费零初始化视图的行为保持原样；未恢复完整offline状态机或 `a00ef1d4` 全实现。

## 主要消费、生命周期与范围

名称读取 `a0601608[kind]`，kind3切名称/特殊图标；kind6 total1用ROM `Total`，total>=2用 `USB MUX`，total0不写名称文本。非零ordinal按格式附数字，Total单项路径不附。随后按原顺序显示单位/电压/电流、写功率初始串、status(slot,0)。数值消费者方向0用IN及低24位89d8f3，非零用OUT及ffd24b，功率按整数、电压/电流按两半字格式化，保留对齐调用。SOC100且小数0用整数，其他按+50选择整数/小数，SOC<10用红色ff5e34，其他widget用06ff8b/标签白色；小时分钟全0隐藏四控件，否则显示并写两数字。颜色参数高字节不作补零假设。

本轮完整审阅 `a00f4610` 和 `a00ef2da` 的store、调用参数及冷块：row/view分别只在s2中用于load；保存寄存器的prologue store保存的是进入时寄存器，不能误认为持久保存新view。业务store为本函数局部颜色字节/半字，向setter/formatter传的是控件、ROM文本、格式串和零扩展标量；没有向持久对象store row/view，也没有将其作为下游参数。`a00f44e8` 从caller只收到标量而不接view。因此**所核主要消费者**不延长栈view寿命。这个判断不把未核的offline消费者、整个callback每条路径或通用setter内部文本分配一并认证。

item及其五缓冲区仍由item所有；converter借用三个资源并只向view产出数值，沿用E02。app由userdata借用，订阅节点保存callback/app但没有retain。栈view没有独立heap分配/free，所核消费返回后本次frame归还使其失效。栈归还不等于app/订阅或页面销毁。

事实为原字节、端口/ABI、读写宽度、分支与unsigned状态、四槽步长、mask短路重读、三个调用返回差异和本地指针不逃逸。业务命名CTK/panel、功率/电压/电流/SOC及颜色由已有字符串/字段关系支持，是分析解释，不是原源码类型名或运行观察。

仍未核：app与item订阅节点的最终注销/释放；全页其他状态机；+34/+38独立读者；全局deinit；通用GUI/formatter/allocator的确切来源版本与最终物理显示。唯一incoming PARAM引用只是有界引用结果，不能证明不存在别的计算注销引用，不能拿控制链 `a01b2966` 当item链销毁。未作泄漏或设备行为判断。
