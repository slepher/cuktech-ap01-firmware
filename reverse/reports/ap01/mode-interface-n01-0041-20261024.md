## 可重建的调用合同

正常使用前提：普通响应handler已安装、非OTA普通业务、有效读写内存和外部串行化由宿主保证。本轮不证明线程安全。在线响应只沿用parser的CRC正确、传输state2、响应cmd匹配当前活动cmd门；直接调用dispatcher不会替调用者建立这些前置条件。

| 入口 | 输入、输出与顺序 |
| --- | --- |
| `0xa019537a(mode)` | 正常mode0..3；本helper本身不作范围检查，先把低byte写`b512/b01d`并同步控制通知，再按**原32bit参数==3**决定4B自定义请求，否则cmd60/len1。无成功返回、句柄或request-id。 |
| `0xa019530a(input4)` | 输入4B可读，首byte非3则直接返回；为3时写`b01d/b512=3`、同步控制通知，之后才读后三byte写全局副本，再submit(cmd60,len4)。输入在通知期间仍须有效；不是先复制完再通知。 |
| `0xa01951e2(view)` | `{u8 cmd@0,u8 len@1,payload*@4}`；len1/4同步复制活动区/固定槽或去重/满槽返回；无入队成功结果。源descriptor/payload不转移所有权。 |
| dispatcher(cmd60,len,payload) | `0xa00a87ac..87d0`：调用`0xa01ad024(b50d,1,payload)`，然后重新读`b01d`；等于3才调用custom查询。普通合同要求至少1B可读，不以len作本分支的读取门。 |
| `0xa01ad024(dst,n,src)` | `0xa01ad036`先清传输state0，再调用既有copy(dst,src,n)。本体没有memcmp、结果码判断、派生事件、allocator/free；返回值无业务合同。cmd60第三参数是原payload，**不是view指针**。 |
| `0xa00a4158()` | 栈view半字`0x005e`、payload=NULL，submit(cmd5e,len0)；无业务返回。查询不会主动填充自定义状态。 |
| dispatcher(cmd57,len,payload) | `0xa00a983e..98ce`：缓存helper复制/比较6B到`b510`，随后按下述阶段协调，最后调用控制变化检测及既有poll selector。正常payload至少6B；调用者给helper固定6，不由应答len限长。 |
| dispatcher(cmd5e,len,payload) | `0xa00a99f0..9a88`：缓存helper处理3B到`b000`；快照非NULL时逐byte同步到`+9/+10/+11`，任一不同则写mask半字=4并同步控制分发，无变化返回。正常payload至少3B。 |

`0xa0191652(dst,n,&view)`的state0、固定n比较/条件复制和变化时`handler((cmd+0x20)&255,0,NULL)`均沿用B03/dock合同。cmd57可先发0x77，cmd5e可先发0x7e；这发生在caller后续协调/快照通知之前，不能合并为一个“应用成功”事件。普通dispatcher对这些cmd值未见本题范围内的模式分支；实际当前handler集合仍由外部生命周期约束。

cmd57协调的必要伪代码（省略日志及继承helper内部，非原源码）：

```c
cache_update(b510, 6, &view); // 先清传输state0；变化时可同步调用当前handler
if (b51d == 0) {
    b01d = b512;             // 收到mode成为期望；不是强制重放早先期望
    b51d = 1;
    set_control16(10, 0);
    query_custom();
} else if (b51d == 1) {
    if (b512 != b01d) {
        if (b01d == 3) custom_apply(b518);
        else mode_apply(b01d);
    } else if (load_u16(b510) != load_u16(b51e)) {
        set_control16(load_u16(b51e), 1);
    }
}
control_change();
existing_poll_selector();
```

这里的全局读取都发生在cache helper的同步回调返回后，不能提前缓存为进入dispatcher时的值。mode不相同时，`mode_apply/custom_apply`会再次覆盖`b512`为期望mode并在提交前通知，因此UI可能始终显示本地期望而不暴露收到的短暂不一致。相同只表示此轮读回mode等于当前期望；没有向原请求返回成功、关联请求序号、持久化证明或MCU内部执行证明。首次阶段0可以覆盖此前期望，是原控制流事实。

`set_control16`即`0xa00a417c(value,force)`：先读`u16(b51e)`，与完整a0比较；不相等或force非0才写低16bit到`b51e`，submit(cmd62,len2,payload=b51e)，否则直接返回。首次调用值10/force0，后续不同调用旧期望/force1。其必要应答续接`0xa00a9cbc..9d02`：cmd62先复制1B到`b50d`并清state0；若companion16不等100，写100并submit(cmd61,len2,payload=b516)，否则返回。cmd61沿相同1B应答复制后返回；这些分支也不解释应答byte。此附属控制值的产品语义未知，不能用10/100推单位。
