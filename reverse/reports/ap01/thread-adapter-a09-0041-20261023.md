## a0051dac：将第二实参转为原 entry 的 a0

分析签名 `void thunk(function1 entry, void *value)`。`a0051db4` 在 a0非零时去 `a0051dc8`；零时设置 `(a0,a1,a2)=(a01c0598,0x37,0)` 并在 `a0051dc4` 调 `a0019672`。这里同样不补造该诊断调用的返回性质。

`a0051dc8` C.MV a5,a0；`a0051dca` C.MV a0,a1；`a0051dcc` C.JALR a5。因此从非零入口分支直接进入时，调用的是原 `entry(value)`，并非 `entry(entry)`、`entry(obj)` 或 `entry(obj+4)`。若原 entry 返回，`a0051dce` 直接 JAL `a00306b4`，保留 entry 的 a0返回寄存器；未恢复该 callee语义或返回合同，也没有给本 thunk 指定可用返回值。

```c
// 非零 entry 的直接局部合同
entry(value);              // call a5 after a0=a1
call_a00306b4(/* a0 is entry return register */);
// inventory boundary ends here; no normal return instruction in this body
```

## 第三核心 a0030ef8：+0x18 的局部生产者

A07/A08 已核调用局部为 `a0030ef8(s1, local_a1, a012f946, s9, 1)`；其中 s9为更早保存原 entry 的寄存器，但此前 A07 的厂商 word未解，本任务不重新证明其跨指令不变量。
