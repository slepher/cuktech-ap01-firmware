### `0xa0191834`：cmd65实际提交合同

伪代码是分析视图，非原厂源码：

```c
void switch_request_view(uint32_t index, uint32_t value) {
    if (index >= load_u8(0x62fcb01c)) return; // unsigned word比较
    uint8_t payload[2] = { (uint8_t)index, (uint8_t)value };
    // 栈descriptor: command@0=0x65, length@1=2, payload pointer@4
    command_submit_a01951e2(&descriptor);
}
```

关键原字 `0xa0191848: 93075026` 为`addi a5,zero,0x265`，`1850` SH到descriptor首半字，little-endian故`65 02`；`184c` SB index、`185c` SB value，`1860`写payload指针、`1864` JAL `0xa01951e2`。本函数只检查index<count，不先检查raw全局指针，不调用getter/capability门，不写I/T遥测或持久化。越界直接return，正常路径提交后直接恢复栈；没有可供UI认证的成功/失败返回值。

descriptor和payload均栈借用，只在同步提交调用期间有效。按既有提交器合同，len2正常路径同步复制至活动区或四槽待发区；也存在未接纳直接返回。调用方不应异步保存栈指针，也不能把函数返回当接纳。运输/MCU执行、应答和超时不在setter中产生新的业务结果。

safe setter `cmd63`及门控完全继承E07：UI的即时勾选/SH仍会发生，即使setter门控未提交；没有“通过capability才更新视觉”的成功门。
