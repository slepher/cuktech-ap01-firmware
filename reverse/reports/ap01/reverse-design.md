## 1. 范围与指令优先级

当前研究目标是恢复足以重建 AP01 功能的 0041 专有业务、硬件接口与必要兼容合同，解释正常行为、状态、接口和生命周期。公共能力允许采用功能等价的开源实现，不要求与原 ROM 的实现或版本完全相同。原厂来源认证与替代可行性分账；全 ROM 覆盖仍保留未知项，不因此允许无种子扫描。0031 历史研究与工具单独按其基线解释。局部合同、函数数量、伪代码导出或 SIM 通过均不能代表原 ROM 完整恢复。

用户当前会话中的最新明确指令优先；本文与管理记录顶部新增规则适用于后续工作，下方带日期的旧派发、停止、并发数、路径、模型修复和实验命令只作历史证据。文档修改不自动启动、停止或恢复任务，不增加并发。实际运行状态由当前管理窗口核实，不能从旧表推断。

当前静态批次只写被分配的 `reverse/reports/ap01/` 报告和 `reverse/analysis/` 产物：不执行固件，不连接设备或外部服务，不做漏洞、异常输入或缺陷验证，不修改安全检查、ROM、生产代码、构建配置或分析器模型，不编译项目，不运行 SIM、QEMU 或历史回放，不推送。历史实验许可和模型修复记录不能替代本轮授权。用户要求收尾即停止新派发和补位，保存已有成果与精确断边。

## 2. 先确认原件和既有证据

1. 确认版本、原件路径、长度、现有摘要记录和地址映射；0031/0041 分开。固定基线不匹配时停用对应地址与结论，不套用另一版本的地址。复用已有原件身份记录，不另造机械哈希清单。
2. 先查父级 complete、最终验收、SIM 覆盖，再查较晚专项、独立复核、交接及机器合同。旧 round2/round4 remaining 或单份 pending 必须与较晚完成记录核对。
3. 旧路径失效时，按 basename、地址、Evidence ID 在当前 `reverse/rehost/`、`reverse/reports/ap01/`、`reverse/analysis/`、`tooling/` 和既有最终 ZIP 成员中定位。ZIP 只读必要成员，不执行、不全解包或复制。
4. 按“已有出处 → 已解释行为 → 证据局限 → 本次精确缺口”写任务依据。缺材料只标缺材料；有限搜索无命中只说明该输入和搜索范围，不证明链条不存在。

## 3. 派发前与扩范围前查重

主窗口负责最终查重和范围决策；启用专职整合席并完成交接后，由整合代理作为认领表及主树的唯一写入者，按主窗口已确认的请求串行登记，回传认领行与管理基线后，主窗口才实际派发。未启用整合席时由主窗口兼任，不能同时存在两名主树写入者。研究者和预调研代理只提出认领或变更请求，不在自己的旧worktree认领。派发消息必须包含已登记的认领行与基线；换整合批次须交接最新表、主树HEAD、未提交改动、任务运行状态及整合队列，不能两个窗口同时派发或整合。

认领单位是“原件版本/身份 + 具体连接 + 对象身份 + 要回答的问题”，任务名或领域名不能替代链条。用已知函数地址、callsite、callback、对象来源及字段偏移表示连接；地址统一写 `0x` 十六进制，保留旧名称/别名以便检索。尚未确认的对象关系标未知，不因字段偏移相同就认作同一对象，也不因名称不同就排除重叠。无需预先知道未知端地址，但须给出已知端及准确的待找连接。

派发前必须：

1. 搜索认领表和相关旧成果中的锚点、别名、对象及问题；表中无行不等于尚未研究。
2. 列出相交的研究中、待复核、已验及未闭行，说明继承范围和真正差集。共用函数但研究不同连接/问题可以并行，必须写清分界。
3. 同一连接和问题已有研究者时，合并、缩小或等待；待复核时安排原认领下的非作者复核，不能另开同题研究。已验部分直接引用。对象身份不清或范围含糊时先标“待消歧”，只核必要既有证据，暂不派重叠取证。
4. 主窗口确认负责人、状态、独占范围、继承证据及查重结论，由唯一主树写入者完成登记并确认后再派发。无真实地址/字段/callback种子或无法说明差集的候选留待登记，不做无种子扩扫。

派发时一并登记完成接口所需的有限依赖边界：起止事件、对象、可追的调用/回调类别、外部边界及排除项。研究途中发现的 caller、callee、callback 或字段若仍属于该边界，且与其他认领不冲突，可在同题继续并在交付时汇总，无需逐字段回管理窗口申请。需要跨接口、跨对象所有权、触及其他研究者范围或突破当前静态限制时，才保存锚点并提交“原认领 ID、新连接/问题、相交行、旧证据、必要增量”，由管理窗口查重登记后继续。无法确认是否冲突时暂停该增量，其余范围可以继续。新任务名、新分支、新报告或 worktree 不构成扩范围授权。

复核引用同一认领 ID，注明复核者及状态，仅核本轮差集和必要的继承前提。重新研究已验或未闭行须注明旧证据的具体不足、改变的输入/新证据和重开理由，保留原结论与历史。中断、交接、完成均更新表，不按超时自动释放认领；管理窗口确认原研究者停止后才移交负责人。无必要增量则报告已覆盖，收缩或换题。

### 3.1 新任务上下文与最小交接包

- 后续新建子代理统一命名为 `领域_类型_两位序号`，例如 `dock_control_research_01`、`dock_control_review_01`、`app_summary_research_01`。领域用稳定的英文小写下划线词组，类型为 `research` 或 `review`；序号在同一领域/类型下单调递增，不回收复用。同题补证/修正保留原名。认领ID仍独立维护，派发和管理表同时记录代理名与认领ID对应关系；合并复核列出全部认领。用户要求此前已有代理名称保留，不追溯重命名或改旧证据路径。
- 每个新研究任务、新复核批次、跨模块任务均新建子代理，显式设置 `fork_turns: "none"`，不继承完整主聊天，也不通过给长期代理换题规避此规则。已停止代理的历史上下文不作为新题的默认输入。
- 仅同一任务内的澄清、补证和交付修正可继续当前代理；发生接口/模块换题或形成新的半小时任务块时，落盘简短交接后新建。新复核者不能是该批成果的作者。
- 派发提供最小交接包：认领 ID、目标/验收边界、原件身份引用与基线、必要地址/对象、独占输出、已有结论及精确差集、必要证据绝对路径/JSON pointer、静态限制、工作量估计。优先给定位，不粘贴整段管理历史、原始工具大输出或完整上轮聊天。
- 规则以本文为统一入口；研究者只读管理记录当前规则和自己的认领行，不默认通读整个滚动历史。交付回传接口结论、分支/基线/commit、产物路径、检查、断边及工作树状态，完整证据留文件；需要时按地址/Evidence ID读取必要窗口。
- 管理角色单独命名：预调研使用`task_prep_research_两位序号`，整合使用`task_integration_两位序号`。席位可以持续设置，但会话按一个有界批次交接后轮换，均新建`fork_turns: "none"`；整合不是技术复核，不占用非作者复核身份。

### 3.2 按约半小时工作量切块，按接口交付

- 研究工作包以约 **30 分钟、参考20–40分钟** 为切块目标，不能把这个目标直接填成耗时预测。2026-10-24用户指出P-17实际仅约6分钟而仍标半小时，属于估时/切块失败，后续必须用本批实测校准。
- 派发前列出组成阶段、每阶段估时、可比历史任务、证据是否已定位、未闭依赖与置信度；按可观测墙钟预测，包含正常读取/工具耗时，排队/异常等待另列。没有有效计算工时数据，不再用“30分钟有效工作量”解释实际仅数分钟的任务。非作者复核单独据差集估时，不统一填30分钟。
- 已定位短setter、单响应分支或公开API胶水，参照本批同类约4–10分钟校准；预计不足20分钟的相关增量必须先并入同接口的未闭阶段，不能每次新建研究任务再机械标半小时。可将数个有独立价值且对象相关的短阶段组成一个20–40分钟接口包；不能跨领域拼凑、追无种子边或深入公共库补时。
- 同接口只剩短差集时如实标短项：在原任务补证或并入相关待复核批次，不另开完整研究/复核链。证据不足、依赖无法定位时写明确未知/阻塞及下一可做动作，不用名义半小时掩盖。提前闭合仍立即交付，不故意等待。
- 每块回答一个可供重建程序使用的完整接口问题，例如“提交请求→队列持有→正常完成/失败→资源归还”，覆盖输入/输出、状态、错误/超时、取消/关闭及所有权；不以一个字段、一个 copy 长度、单个 helper 或检查项数量作为独立任务。
- 预估不足 20 分钟的相关小差集合入同接口任务；超过 40 分钟则按有独立验收价值的状态机阶段切块，例如“请求构造与交接”和“完成/取消与归还”，明确两段共享合同，不按反汇编字节数机械拆分。完整接口可以由多个块组成，所有必要阶段合并后才能标接口闭合。
- 派发注明估算及假设、预期可用成果、允许的必要依赖和停止边界。接近约 30 分钟仍无法闭合时回报已证事实、阻塞/新种子与剩余估算；保存为部分恢复或阻塞项，由管理窗口判断替代、重新切块或续作，不无界滚动、不重做已有段、不因到时自动移交。
- 使用可获得的开始/结束时间记录实际墙钟时长，并注明工具等待或中断；只在运行环境提供用量时记录 input/cached/output/reasoning 等 token，不用报告行数或估计值冒充实测用量。没有有效工时数据就不宣称墙钟等于有效工作时长。
- 每批依据“闭合接口/可独立使用阶段、实际耗时、可获得的 token 用量、未闭原因”调整下一批估算，不以运行席位满额、报告数量或静态检查数量衡量产出。
- **两项准入缺一不可。** “一个完整的小阶段”不自动成为独立研究包；还必须有根据近期实测可预测的20–40分钟真实未闭工作量。函数个数、原字节数、检查项数或给若干阶段机械相加不能代替预测。已验父级、充分定位的材料、现成提取器和公共API止边都要从剩余工作量中扣除。
- **校准必须改变包的实际范围。** 连续研究任务仅数分钟完成时，重新盘点同接口尚未闭合的输入、持有、回调、超时、关闭和归还连接，把相关真实差集合并后再派；不能只把下一包改称“3–8分钟”而保留同样的小块，也不能重复研究已验根或公共库补时。派发说明必须写本次合并了哪些连接、相对前包增加的实际工作，以及估算依据。
- **短尾单列处理。** 预计不足20分钟且没有合适同接口阶段可合并时，列为“短尾待合并”，在原任务允许边界内补证，或纳入相关非作者合批复核，不再为每段另开完整作者→复核链。跨原边界仍须查重登记。仅剩短尾或没有足够真种子时如实报告，不能为了保持满席或三份库存制造研究包。
- **复核单独计时。** 必要非作者复核可以短于20分钟，但须合并同接口相关差集，标明真实预测；它不能被统计为一个半小时研究包，也不能将三个短复核包宣称为三份20–40分钟研究储备。提前完成仍立即交付，严禁等待凑时长。
- **先取时钟。** 执行代理的首个工具调用先记录UTC开始时间，技术冻结、提交完成和停止分别记录；正常工具耗时包含于墙钟，排队、中断和补修观察区间另列。没有完整起点只能报可观测区间，不据此伪造总工时或有效计算时间。

### 3.3 专门预调研代理、预分配队列与动态切块

- **席位分工。** 后续配置为三席执行研究/非作者复核、一席专门预调研、一席专职整合，共五个子代理；用户最新明确数量优先，本文修改本身不启动或加席。预调研和整合都不是额外研究/技术复核席。预调研命名`task_prep_research_两位序号`，新建`fork_turns: "none"`。按一个补位批次/接口域提供最小上下文；换域或新批次保存交接后新建，不借长期角色跨题积累上下文。没有关闭/释放工具时如实记录限制，不承诺无限新建或跨题复用绕过上限。
- **提前准备任务。** 预调研代理承担原先主窗口临时找题、查旧覆盖、确认材料和拼工作包的工作。优先底座协议与应用接入，先核父级complete、较晚复核、当前认领和证据可用性，分清已验前提与真实差集、可达依赖及公共API边界。缺材料/无种子、重复已验、纯公共库内部不列为可派。只核足以定题的必要定位，不抢做完整研究；发现必须先做实质取证才能定题时，明确标待消歧，不伪装成准备完成。
- **保持预分配数量。** 后备目标为3份真实可派包，表示执行席位之外的库存，不把已取走执行的包留在库存。分别列“常规研究可派（通过20–40分钟实量准入）/合批复核可派（真实估时）/短尾待合并/条件模板/待消歧/缺材料”；只有前两类计可派总数，并分别报告其数量，不能用短尾充常规研究数。不足3份如实报告，不为满额制造微任务、重复负搜或跨域拼量。
- **前置复核模板。** 每个在跑作者的原边界明确后即可准备条件复核模板，先落盘给出包ID和精确段落定位。作者实际交付且确认停止后，补齐最终commit、修正差集和完整实测时间，依赖满足才转可派；此前不计库存。不能等作者结束后才从零组包，也不能把尚未交付的未来复核算已备齐。
- **每份包能直接交接。** 包内包含候选代理名/认领建议、接口问题、原件和管理基线、已有覆盖/精确差集、必要VA/对象/callsite/callback及证据绝对路径/JSON pointer、起止/有限依赖/排除项、组成阶段及分别估时、同类实测依据与置信度、验收条件、独占worktree/分支和输出建议。提供所需的最小派发文本，主窗口不用重新搜索整套资料。预分配是候选，不授予认领，不修改唯一认领表、不自行派发或接管其他任务。
- **完成消息同时触发两条队列。** 主窗口收到结束消息后，将认领ID、接口结论、commit、起止/墙钟、等待/中断、可得token和断边同时交给预调研席及整合席。预调研更新覆盖和包大小、补回被取走的库存；整合席立即接收交付，按第7节验收范围、合并、转存和清理，不等主窗口攒批。主窗口核最新冲突/依赖/授权及3.2实量准入，经唯一写入者登记确认后派发。主窗口处理技术争议，不能用管理整合代替非作者技术复核。
- **按当前执行表现动态调大小。** 预调研代理接收进度回报和完成实测后，结合最近可比任务的实际差集、材料定位程度、阶段耗时与当前剩余依赖，更新尚未派发包的阶段、合并/拆分及预计墙钟；研究与复核分别校准，等待/中断单列。多项任务实际只需几分钟时，应先排除已覆盖/缺材料的候选，把同接口真实未闭阶段合并成有实质工作量的20–40分钟包，不能把每阶段名义时间相加或直接抄30分钟预算。超过40分钟则按独立可验收阶段拆分；只剩短差集便并入原任务或相关复核，不另起完整链。不得故意等待、扩大无种子范围或深挖公共库补时，也不追改正在执行任务的边界来凑时长。
- **交付与独立性。** 预调研使用自己的独占worktree/分支/报告，按新规则交commit；整合席合并后保留可读队列，ignored产物按第7节转存。成熟包先落盘并给包ID/标题/定位，派发只补动态基线、依赖和授权边界，不反复粘贴整包或历史。记录真实计量；预调研不等于业务已验，实际参与技术取证者不能复核该题。静态限制不变，不创建下级代理。

### 3.4 专职整合代理与主树单写入

- **实际负责整合。** 整合席使用`task_integration_两位序号`、`fork_turns: "none"`，负责交付队列、范围与格式检查、commit合并、ignored原路径转存核对、工作树/已合并分支清理、状态与整合记录。它执行主树操作，不是另设一位只汇总建议的预调研；也不替代技术复核、独立取证或扩大已验边界。
- **交接后只留一名写入者。** 主窗口先交接主树HEAD、暂存/未暂存/未跟踪及ignored保留事项、唯一认领表、任务运行状态、各交付SHA及阻塞。整合席接管后独占主树文件、认领表和Git写操作；主窗口只提交已确认的登记/范围决策和派发请求，读取登记确认及管理基线后派发，不同时修改主树、暂存、commit或merge。未启用时由主窗口兼任，不能含糊共享写权限；其他聊天写入须先协调交接。
- **派发即包含本地整合授权。** 在已交接管理范围内，整合席可按精确路径完成登记、合并、转存和清理，无需逐项再请用户批准。禁止推送、修改ROM/生产配置/分析器、夹带他人改动；发现冲突、主树并发改写、缺材料或技术争议时保存现场并回主窗口裁决，不能reset/clean/force掩盖问题。原任务分支基线不随主树推进而移动。
- **交付即入队，积压优先处理。** 不等整批结束才整合。目标是持续消化已结束任务；积压持续增长或整合席受阻时，主窗口先恢复整合能力、优先消化交付，不继续靠新派研究堆积worktree。正在执行的任务正常收敛，不能为排队自动释放认领或强清成果。
- **分开记录三种状态。** 运行状态记录运行/停止/中断；技术状态记录作者交付待复核/补修/限定接受/未决；整合状态记录待合并/已合并待转存/已转存待清理/清理完成。已交付commit但未合并要称“整合待办”，不能统称“研究未完成”；复核中断且有未提交文件须明确，不能按已交付清理。先合并的作者成果仍保持待技术复核。
- **完成标准。** 整合席回报交付SHA与主树整合SHA、范围/引用检查、非作者状态、转存清单与逐文件SHA或字节核对、忽略规则检查、任务停止确认、tracked/untracked及ignored无遗留、绝对路径边界和无force清理结果。任一条件不足就保留树并明确卡在哪一步，不把仅复制文件或status干净当完成。下一整合批次先提交管理记录并交接后再换独立上下文。

## 4. 独占工作区与工具隔离

研究、非作者复核和预调研按当前授权使用独占worktree、分支及同名报告/analysis；分支默认`codex/`。整合席作为唯一管理写入者按3.4节直接管理主树/管理分支，不借另一个工作树只复制文件冒充主树整合。任务树从登记时最新管理提交创建，记录启动基线，运行途中不移动；每次shell显式工作目录，PowerShell用`login:false`避免登录脚本改目录。

派发授权研究者/复核者在独占分支精确提交本任务报告、必要合同/清单和复验源码，无需逐次申请；不扩大研究或授权推送。整合席按3.4节完成主树验收合并，未启用时主窗口兼任，不能以口头指导或手工复制已跟踪成果代替commit交付。

研究者不修改主树、共享索引和管理认领表，不撤销他人修改，不自行接后继或创建下级 agent。原件、留存和工具可以从主仓库绝对路径只读引用，不复制工作区、不覆盖旧证据。临时状态和日志放独占 analysis 目录，不提交账号、密钥或私有会话。

使用 REA 时先复用匹配原件与 profile 的留存证据、数据库或会话。需要新分析时确认原件、语言、映射及 profile 身份，使用隔离的数据库、缓存和会话；不切换共享 REA 或修改全局/私有分析器模型。工具无法隔离就报告管理窗口，继续可做的留存分析。只关闭自己创建的会话，不影响他人进程。

## 5. 有界静态分析与语义恢复

围绕已登记的问题，从已知入口追踪必要数据、状态、调用及清理，回答正常行为。先读留存和摘要，再取最小必要窗口；不重复整函数导出、全资源提取、分类重建、PNG 解码、全源码复制或机械哈希账。重读旧字节属于复核，不能算新增功能。

恢复内容至少覆盖问题所需的参数/返回、调用顺序、条件与状态转换、数据布局、所有权和生命周期。保留重读、位宽、符号扩展、失败分支、清理原序、返回判断和间接 ABI；不能为“合理”而修正原程序，也不能用短 helper 代替原问题闭包。

函数边界、厂商指令及关键宽度/ABI 争议须核原字节与指令，不能只信反编译。`custom0`、`unaff_`、`extraout`、no-return、未知指令和错误 body 边界必须具体定位；未知编码不改成 NOP，不手工补满区间声称完整。工具直接边只作已知覆盖，遗漏的间接调用和混入数据须明示。

### 5.1 开源替代优先，停止库内部默认深挖

先判断公开实现是否满足目标功能，再决定是否需要逆向。NuttX、LVGL、libuv、文件系统、分配器、TLS/基础算法、JSON、PNG/GIF，以及 libc 的 formatter/copy 等，已有可用替代时停止默认追原内部实现；不能为证明原库精确版本而展开整库，或将其登记为业务接口的必经后继。候选及局限见[替代与缺口评估](reverse-gap-and-opensource-replacement-20261024.md)。

替代决定保留简短记录：目标能力、上游/选定版本或候选、公开 API、需要的错误/所有权/线程约束、平台适配和未验证项。能作为实现起点不等于已移植或实机已验；原厂来源未明仍记未明，不因此批量认证历史函数。字体/图片原件、无线二进制和底座 MCU 不因可复用而变成开源。

只在继续调用原厂二进制需要精确 ABI/对象布局、已观察到影响目标功能的厂商差异，或替代方案确实缺必要能力时，研究最小边界；登记具体理由、调用点和停止条件。重点恢复专有协议、厂商业务胶水、硬件适配与真实调用/回调合同，不默认下探公共算法内部。不同对象即使类型名近似也不能混用生命周期合同。

## 6. 证据与报告

按 2026-10-24 用户清理要求及后续澄清，所有导出文件保留在项目原路径，仅取消 Git 跟踪并清除历史副本，不移出项目目录。Git 只提交必要合同、结论、资源/来源摘要及复验源码；忽略规则与历史路径解释见 [分析材料保留规则](../../analysis/README.md)。本节其余证据要求仍适用，留存路径可以指向本地忽略文件或归档，不能要求为取证完整性重新提交大批指令记录。

独占worktree新增导出、日志等中间产物由整合席（未启用时主窗口兼任）转存主树相同相对路径，保留报告引用并确认目标受`.gitignore`覆盖。先复制逐文件核对，再移除任务树对应副本，按第7节完成。原路径指主树原相对路径，不要求长期保留临时worktree。

每条结论提供可定位的原件身份、地址/偏移、必要原字节或指令、Evidence ID/留存路径及工具/profile 来源。工具预览截断不等于分析缺失：先取留存分页或必要部分，避免仅为完整响应重跑生产分析。不能把不完整预览当完整 JSON 或完整函数。

报告固定分为四类：继承结论、本轮复核或纠正、真正新增、未闭精确边。每类区分事实、推断和未知，并交代证据类型：原厂字节、第三方源码/作者记录、静态推断、宿主测试、SIM/QEMU 或实机。SIM/照片/安全替代只能说明相应范围，不能外推 ROM ABI、驱动、云端或实机成功。

交付应包含：认领 ID 与问题/独占范围、查重依据、业务行为、函数地址/参数/返回/调用、必要伪代码/结构体/状态转换、所有权与释放、证据及来源、恢复程度、实际静态验证、精确断边及一个有种子的后续建议。伪代码注明并非原源码。不得以新增文件数、函数数、时长或导出量作为完成标准；问题得到有证据答案或明确可定位断边才算本项交付。

报告围绕一个接口汇总上述四类内容，不为每个 helper 重复创建全套报告与规则。首部列“接口已闭合 / 可独立使用阶段已闭合但接口未闭 / 部分恢复 / 已覆盖无新增 / 可用替代方案”之一，并列预估/实际时间、用量可用性与下一步。明确断边的报告可以交付，但不能标记完整接口已完成。

## 7. 独立复核、整合和收尾

接近交付先报结论、重叠检查、剩余验证、阻塞和真实后继种子。研究作者不能自验冒充独立验收；管理窗口只做范围与整合检查，技术争议交研究者/非作者复核者。研究成果可以先记待复核，不能先标已验。复核可以复查必要旧字节，但复核新增为 0 就如实记录。

默认将同接口的相关字段、helper、连续阶段及小差集合成一个复核批次，由未参与该批作者工作的新代理使用 `fork_turns: "none"` 独立复核；不再为每个小增量各派一次全流程复核。批次只给接口摘要、差集、证据定位、验收表及已验前提，避免逐份报告重复读历史。不同作者的成果合批时，复核者必须对整批均为非作者；做不到就分批。

复核围绕完整接口检查输入到结果/归还的连贯性、阶段间对象身份、所有权、位宽/ABI、失败/超时/取消/关闭以及必要兼容约束。底座协议、持久化、OTA/启动等关键边界不因合批免审。可逐项接受或纠正；只有必要阶段全部接受且不存在影响目标行为的断边，才标接口闭合。复核发现的修正先交作者，修正后的必要差集由复核者再确认，不重验整批无关内容。

复核按差集与近期同类实测单独估时；例如已定位短接口合批预计6–10分钟就明确标注，不能一律写半小时。较大批次以20–40分钟为参考，过大按接口/独立阶段分批，不能为了减少派发而一次装入整个 ROM。整合席持续接收交付、更新状态和后继，不等整批结束，也不逐字段往返登记。

按以下顺序交付和收尾，启用后由整合席独占主树写入及清理，未启用时主窗口兼任；交付入队不因补位而延后：

1. **任务分支本地提交。** 研究者/复核者检查差异、必要引用和格式，完成本轮静态范围内的验证，按精确路径提交报告、必要合同/清单和复验源码。派发已包含此授权，不再等待额外提交许可；不强制加入被忽略的中间产物，不推送，不为凑检查运行历史回放或全项目构建。部分恢复、阻塞或停止任务也提交已有有效成果，如实保留未决项。
2. **交付 commit。** 回报认领ID、分支、启动基线、commit SHA、报告/产物路径、实际检查、未决项和工作树状态，另列尚待转存的 untracked/ignored 中间产物。没有新增可提交成果时明确说明原因，不创建空提交冒充交付。
3. **主树验收合并。** 整合席以交付commit检查范围、差异、引用及非作者状态，按预授权合并到管理分支，优先fast-forward或保留祖先关系的merge。不得只摘口头结论、复制文件即称完成。技术验收仍由非作者完成；先行整合作者成果标待复核。需修正时交原作者补commit再整合，技术争议回主窗口，不由整合席自验；记录交付SHA/整合SHA和认领行、断边及后继。
4. **转存中间产物。** 确认任务已停止，列全 tracked/untracked/ignored 文件。应入库的未提交成果先补交 commit 并合并；不应入库的中间产物转存至主树相同相对路径，确认忽略规则生效。先复制、核对文件清单与逐文件字节或SHA256，再移除源副本；目标同名且内容相同则复用，内容不同不得覆盖，先解决命名冲突并修正必要引用后再清理。转存记录保留来源/目标路径和核对结果；账号、密钥及私有会话继续按私有留存规则处理。
5. **确认干净后清理。** 主树已合并全部任务 commit，全部中间产物已保存并核对后，确认任务树 `git status --porcelain` 无输出，另用 `git ls-files --others --ignored --exclude-standard` 核实没有尚未转存的 ignored 文件；仅 status 干净不足以证明产物安全。确认解析后的任务绝对路径位于该批任务根目录内并退出该目录，再用不带 `--force` 的 `git worktree remove` 清理，随后用 `git branch -d` 删除对应本地任务分支。禁止以 `reset --hard`、`git clean`、force 或 `branch -D` 掩盖未提交、未转存或未合并问题。若历史 cherry-pick 导致祖先关系不成立，记录成果等价性和阻塞，不强删。受阻则保留并注明原因，不操作主树、其他任务或远端分支。

完成行、报告、证据引用、提交/合并及转存记录继续保留，未闭不写成全局完成。清理 worktree 不等于技术验收通过，也不删除主树中的本地中间产物。此规则取代历史“保留分支”及“无提交复制整合”的约定。

以下保留原文方法，仅适用于对应 0031 基线，不替代 0041 的 profile、映射或证据校验。

分析入口为 `tooling/scripts/__main__.py`，依赖只读上游的 `core/firmware_image` 与 Capstone。工具只在 0031 精确长度、SHA 和 CRC 校验通过后使用固定地址，输出 JSON 索引、有限扫描的候选引用及选定窗口原字节/反汇编。

引用识别仅覆盖直接跳转和相邻地址构造；混入数据、间接调用遗漏和未知厂商指令均须标注。以已知指令检查符号扩展、PC 运算和指令宽度，不能把候选边当作完整调用图。

分区、ROMFS 启动卷和 8 项内置应用表按固定位置和结构校验；输出来源偏移、配置栈和入口。配置栈不等于峰值，编译时分区不等于设备完整 Flash 备份。依据见[阶段报告](report.md)和[分区/启动复查](knowledge/0031分区与启动入口复查.md)。

工具仅读原件，不执行固件函数。输出目录须已存在，同名结果拒绝覆盖。历史业务尺寸探针已归档到 `reverse/migration/scripts/`，其输出仅说明当时源哈希下的数据布局，不构成本项目的业务依赖或当前资源预算。
