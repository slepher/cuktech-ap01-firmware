# 0041 多应用屏幕宿主实施计划

日期：2026-10-20；本版已纳入原件追加验证和codex_status现状，取代本文件早先的从零实现/静态注册计划。

依据：[架构目标](multi-screen-app-host-0041.md)、[现状同步](codex-status-host-baseline-20261020.md)、[追加验证与证据](screen-host-append-validation-20261020.md)、[接口收敛稿](screen-host-interface-0041.md)。

## 1. 已确定的方向

- 0031维持维护/恢复定位；0041提供多应用宿主。保留原厂页面、Pet GIF、传统OTA和独立救援。
- 采用win内追加普通页面的独占root模型。原厂页面本身也是普通LVGL对象；+0x3c kind约束属于屏幕层窗口查找，上一版疑虑已纠正。
- 优先复用已有VA 0xa005d180事件注册挂钩、长期堆Runtime、原件槽尾布局和保护范围。早期0xa005d0b6前追加会改变初始化active种子，本版不选该点。
- 提取现有codex_status平台能力，保留业务/Bundle/渲染；不重写已经运行的维护和业务协议。
- 最终每个模板有独立root，并与另一应用共存。单root内部轮换8模板仅可作为提取过渡，不能作为目标完成。
- 每应用声明容量，UI线程原子替换本应用screen-set；稳定ID映射与逻辑顺序独立于物理child索引。总池容量按应用清单和内存预算确定，不沿用全局8槽限制。
- 每应用50ms隐藏态UI轮询保留present/retire链路；活动页1000ms tick仅做可选刷新。两屏滑动期间帧及descriptor分别有效，实际draw才确认displayed。

## 3. 实施顺序

| 阶段 | 修改范围 | 交付与退出条件 |
| --- | --- | --- |
| P0：现状与可行性 | 本轮报告/证据/检查脚本 | 本轮机制级结论已完成；真实创建/失败路径转入P1，不把有界执行记成整UI通过 |
| P1：最小真实ROM适配探针 | 本仓库新增0041窗口适配与隔离探针，复用现有QEMU链 | 在UI线程较晚挂钩创建两个真实root并返回原厂；核对0..8对象指针/计数不变、有效tag、分配失败、删除及重建；截图显示两页实际同时移动。通过后冻结对象/LVGL绑定 |
| P2：宿主核心与ABI | app_screen_0041.h/.c及一个宿主检查程序；SIM只加适配 | 固定应用清单、有界root池、screen-set事务、ID/物理索引映射、输入焦点与prepare/animation状态；模拟事务失败/并发/过期结果；纯核心无ROM地址/LVGL依赖 |
| P3：codex_status提取接入 | 逐项提取native_0041.cpp导航/图像适配，业务留原仓库；新增本仓库共享接口 | 保留present/retire/displayReason、50ms队列、单active context、绑定/维护顺序；过渡可单root，随后8模板独立root；配对/维护只有一套执行器 |
| P4：动态Bundle与完整导航 | 复用现有Bundle事务、真实X11/RV32验证入口 | 增删重排按稳定ID、旧帧退役、等待原因及恢复不抢焦点；Pet↔应用集合↔Settings双向，原厂条件门控/屏保/弹窗回归；两应用共存 |
| P5：完整候选与资源验收 | 提取现有槽尾构建/链接/放行链，补充新模块清单 | 检查允许补丁范围、GIF/ROMFS/PEC/传统OTA不变；RV32段/栈/重定位/两帧峰值通过；精确候选原生OTA、同NOR及无稳定记录回切通过 |
| P6：新版本实机验收 | 后续部署步骤单独制定 | 先证明独立救援/回切，再验证多页、连续旋转、动画、更新恢复与长期资源；仅按新版本证据登记，不继承34全部实测结论 |

P1真实root创建/绘制、P2宿主核心与P3代码提取已经落地，P4/P5的实际通过项见重构交付记录。P6实机部署按用户要求暂不执行；ABI仍为实验v1，不能将离线结果替代实机验收。

## 4. 必须保留的回归

| 场景 | 要求 |
| --- | --- |
| 无应用/0屏/全隐藏 | 原厂Pet/Settings原路径成立，维护服务继续工作 |
| 两应用三屏、codex_status八模板加另一应用 | 容量按声明之和；无静默裁剪；每逻辑屏各自root |
| 页面隐藏、重排、删除/复用 | 不删除或重排物理root；相同ID保留绑定，旧句柄/revision不得操作新页 |
| 创建或绑定失败、未知Bundle结果 | 不暴露半个新set；已退役旧内容不再调用；内置恢复和独立维护可用 |
| 动画/准备中旋转及主动切页 | 不重入，不累积输入队列；prepare有期限；目标失效或系统抢占取消事务 |
| 帧准备/两屏滑动 | 源快照不变、目标激活/生成成功才启动；完成前两份descriptor/像素均有效 |
| 焦点锁/3秒逃生 | 先解锁后通知；一次按住只触发一次，释放不补短按；UI阻塞不在保证范围 |
| 原厂页发布Bundle | 不抢焦点；waiting_for_template_page |
| 模板页发布/重排/删除 | 按稳定ID恢复；删除回新initial ID；用户输入取消自动返回；配对/维护优先 |
| displayed | 仅当前generation/模板实际draw；动画完成或image提交不能代替 |
| UI重建/休眠/屏保/全局弹窗 | 生命周期不使用旧root；系统状态优先，唤醒输入不顺带切页 |
| 维护与OTA/回切 | 业务/Bundle失败不封死服务；无稳定记录仍可普通OTA/手动切槽；只查询未知原事务 |

## 5. 资源与证据要求

以当前34为对照：Runtime2088B（含Business1776B）、I4像素38400B、含调色板图像38464B，均来自现有专项记录。新root池、tag、两帧、render临时区、队列及线程栈分别量测；稳定/滑动/安装/失败重试峰值分别记账。不得以至少多38464B的动画下界替代完整预算，也不为8模板预分配8整帧。

验证顺序为纯核心检查 → SIM真实输入/画面 → 原件局部函数/真实LVGL → 精确完整候选 → 实机。每份报告保留原件/源码/工具/产物哈希和mock范围。既有QEMU仍有整ROMUI缺口，遇到缺失路径如实记录，不能通过放宽断言宣称完成。
