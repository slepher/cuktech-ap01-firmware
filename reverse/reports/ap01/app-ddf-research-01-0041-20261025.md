## 正常 ACK 与输出来源

令 C 为 result a0，ACK 为 a1。a00c6fce 调既有原地 v3 tokenizer a0191d52(ACK,stack_tokens)；仅 token 数 n>0 才继续。n<=0 直接返回−1，可选日志；不调用本层清缓存和 reply，不能假设坏 ACK 同 error 回调。

a00c703c..7054 取 token0，strlen→a005fdfa 转数，**仅 sh 低16位**至 C+28c；输出时 lh 有符号加载。正常 level<=2 且 n==2 时，C+294=token1+1，C+290=strlen(token1)−2；这是 ACK token 内部切片的**借用**，没有分配/copy。其引号/长度正常前提继承，不做异常探测；n!=2 不更新这两槽，本层也不清它们。

builder 栈三槽来自 C+74 buffer、min(unsigned C+78,0x558) capacity、初始长度0。a01a4e04 初始化，a01b3872 开对象，a01b3574 写顶层 id=C+3c，a01b371c 选 result，再开对象。code!=0 时只写 result.code，然后走共同 close/归还/finalize。code==0 时按 level 分支：

| level byte | 输出结构与来源 | ID 选择 |
|---:|---|---|
| 0 | result.code 与 ACK slice；modules 数组，每个 module 的缓存片段，加 services 数组；每个 service 的片段，再加 properties/events/actions 数组 | module32 的 +12 与 service32 的 +12 **全32位相等**；叶 helper 的 mid/siid 参数取 service 的 +12/+16 **低字节** |
| 1 | result.code 与 ACK slice；modules 数组，仅每个 module 的缓存片段 | 全部 module，链表次序 |
| 2 | result.code 与 ACK slice；modules 数组，module 片段和 services 数组，仅 service 片段 | module 与 service +12 **全32位相等** |
| 3 | result.code=0；services 数组，仅 service 片段 | service +12 全32位 == C+284 全32位 |
| 4 | result.code=0；services 数组，service 片段及三类叶数组 | service +12 全32位 == C+284；叶参数为 service mid/siid **低字节** |
| 5 | result.code=0；三类叶数组，直接放在 result 内 | 参数为 C+284/C+288 **低字节** |
| 其他 | 本层 result 对象为空，仍走共同尾部 | 根未拒绝该值；不外推业务合法性 |

## 所有权、锁、close/finalize 和返回

所有缓存片段与 ACK slice 在输出阶段都以借用 ptr/len 同步交 JSON/raw-format API；应用层未把它们另存成新的 node。a01b67e6 的内部复制/格式化保证止于 API，不展开；故“缓存归还前已发出所有格式调用”是原字事实，完整库内部 copy 保证不是本次证明。API 替代可使用公开 JSON writer 和 slice append，但必须保持调用者 buffer/capacity、错误标志/finalize 和同步消费要求；未选定或移植具体库版本。

共同尾部 a00c70e8..710c：先关 result 对象(a01b36b6)，再关顶层(a01b380c)，然后调用 a00c6efe(C+208,C+2c0)，最后 finalize a00602e6(builder,0,0)。输出构造/遍历阶段**没有本层加锁**；锁只包围清链。不能从 transfer 和清链各自有锁推断 traversal 并发安全。

a00c6efe 的基址 B=C+208；若 mutex!=0，调用 a005f3d8(mutex,−1)，未分支检查其返回；依次传 B+90/98/a0/a8/b0（恰 C+298/2a0/2a8/2b0/2b8）至 a00c6eba，最后 a01b3c8c(mutex) 解锁。mutex==0 时仍清全部五 head，不加锁。它不销毁 mutex、不清 C+2c0。

a00c6eba 保存 next 后遍历到 sentinel；每节点先 a006929a(node) 通用 unlink，再若 payload非空 free(node+28)，再 free(node)，移到已保存 next。**不保留选中过的缓存，五类全部归还**；没有显式 memset sentinel/状态槽；head 恢复空链依赖 unlink API 的既有约定，止其内部。C+28c、C+290/+294、callbacks+6c/+70 在本层不清零，因此后者不可误当归还后仍有效的 ACK 片段所有权。

finalize成功后 a00c7114 清栈 reply 描述的36B区域，设置：描述+0=C+3c；描述+1c=strlen(output_buffer)；描述+20=output_buffer。实际传 reply(a0=&stack_descriptor,a1=C+68)，函数指针=C+64；返回值原样成为 result 返回。此处不保证 reply 下游保存/复制 buffer 或栈描述，不延伸其持有寿命。

finalize非0：此前五缓存已归还/锁已释放；调用 shared error a00bd7fa(C,−9998,"exceed max rpc size, not support")，直接返回该 API 值。没有重建缓存或重复清链。各写入 API 返回没有逐项分支，本层只在 finalize 门集中判断。

error callback a00c6f56(C,status,message)：先完整执行同一 a00c6efe(C+208,C+2c0)，再 a00bd7fa(C,status,message)，原样返回 shared error 的结果；status/message 参数跨清链保留。其归一化/输出细节沿 Q22 已交 shared API，不重复内部取证。区别：tokenizer n<=0 的早返不清链；有效 token 后的 status!=0、正常/空结果、finalize失败都会先清五链。
