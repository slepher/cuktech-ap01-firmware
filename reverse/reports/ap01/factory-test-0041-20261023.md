## 启动门控与资源生命周期

初始化是外层 `a005a736` 的内联业务块，不虚构单独函数入口或布尔返回。热片段 `a005ab96..a005ac03`，冷片段 `a005b34c..a005b7f9`；后续继续 MiIot 初始化。

1. stat `/dev/gpio3`，要求 `(st_mode & 0xf000)==0x2000`，再以 flags 原值 3 open，存输入 fd。stat/类型/open 失败记录并离开工厂初始化。
2. 用 `ioctl(input,0x2303,&type)` 查询 pin 类型。成功则进行 3 次读取：每次先清局部 value，再调用 `ioctl(input,0x2302,&value)`；失败只记本次日志，成功累计 good/sum，且若尚有下一次尝试就调用延时函数 `a01b4ff4(10000)`。按既有接口语义推断约 10 ms，原始参数 10000 是指令事实。3 次全失败则关闭输入并离开。
3. 有成功读取时，最终 LOW 条件为 `sum < ((good+1)>>1)`，否则为 HIGH。两次有效读取时的一高一低判为 HIGH，不能笼统写作严格多数表决。
4. pin 类型查询失败分支会记录、close 输入，再令最终判断走 LOW 分支；按原指令保留，未替换成提前退出，也未进行异常输入验证。

最终 HIGH 路径记录退出测试模式，直接 open `/dev/gpio12`（此分支没有单独 stat），成功则 `ioctl(output,0x2301,0)`，然后依次关闭输入、输出；写失败也继续关闭。open 输出失败时关闭输入。本分支未观察到显式清 active；不把冷启动 BSS 初值写成每次退出都会清零。

最终 LOW 路径 stat 输出设备并检查字符设备类型，再 open flags=3，初始化 timer `a009d106(loop,&timer)`；这些失败路径会关闭已取得的 fd。成功后：

```c
// 仅表示初始化内联块的成功尾部。
if (ioctl(output_fd, 0x2301, 0) < 0) log_write_failure();
phase = 0;
// count 没有在这里重置。
int r = timer_start(&timer, factory_tick_a009f178, 750, 0);
if (r < 0) {
    log_timer_failure();
    close(input_fd);
    close(output_fd);
} else {
    active = 1;
    log_started();
    log_effect(/* ON */250, /* OFF */750, /* cycles */3);
}
```

初始写失败只记录，仍启动 timer；timer 初始化/首次启动失败后的已核清理是 fd close，未观察到额外 timer close。成功路径保留两个 fd。不要添加未出现的关闭、标志复位或返回码传播。

## 单次 timer 自行重排

callback 参数在此逻辑中不参与对象选择，直接访问上述全局状态。每次重排均为同一 callback，repeat=0；重排返回值未检查。

```c
void factory_tick_local(void *unused) {
    if (active == 0) return;
    switch (phase) {
    case 0:
        if (ioctl(output_fd, 0x2301, 1) < 0) log_write_failure();
        phase = 1;
        log_ON_completed(250);
        timer_start(&timer, factory_tick_local, 250, 0);
        return;
    case 1:
        if (ioctl(output_fd, 0x2301, 0) < 0) log_write_failure();
        count += 1;
        log_OFF_completed(750, count, 3);
        if (count <= 2) phase = 0;
        else { phase = 2; log_three_cycles_completed(3); }
        timer_start(&timer, factory_tick_local, 750, 0);
        return;
    case 2:
        if (ioctl(output_fd, 0x2301, 1) < 0) log_write_failure();
        log_constant_ON();
        return;  // 不再次排 timer、不清 active、不关闭 fd
    default:
        return;  // 不重排
    }
}
```

GPIO 写失败不阻止 phase/count 推进或重排。callback 不重新读取 GPIO3，也没有恢复出通过输入变化退出测试的机制。这是本片段边界，不是整个 ROM 不存在退出逻辑的证明。

按冷启动 count=0、首次启动及各次重排成功、忽略调度延迟推导的**数字写值**如下；它是静态时间算术，不是实测灯光：

| 相对时间 ms | 写入值 | 写后 phase/count | 下一次 delay ms |
| ---: | ---: | --- | ---: |
| 0 | 0 | 0 / 0 | 750 |
| 750 | 1 | 1 / 0 | 250 |
| 1000 | 0 | 0 / 1 | 750 |
| 1750 | 1 | 1 / 1 | 250 |
| 2000 | 0 | 0 / 2 | 750 |
| 2750 | 1 | 1 / 2 | 250 |
| 3000 | 0 | 2 / 3 | 750 |
| 3750 | 1 | 2 / 3 | 无重排 |

初始化效果日志打印 ON=250、OFF=750；phase0 日志写“ON time completed(250)”，phase1 写“OFF time completed(750)”。这些标签、实际等待时间、GPIO 数字值须分别保留。无极性证据时，不由日志反推光学 ON/OFF，也不调整状态机来使标签一致。

## 剩余未知与覆盖边界

启动门控、三次采样规则、错误分支、fd 取得/失败释放、timer 初次启动、自重排和三轮后保持已形成局部功能合同。仍缺全部外部状态读写者、成功进入后的 stop/close/fd 释放、重复初始化约束、物理引脚/极性，以及其他量产功能与工厂 UI 的关系。active 保留为 1 不等于仍有周期 timer。该片段没有独立 pthread 创建证据，不能据目录名补造“工厂测试线程”。

已恢复的工厂 10 秒蜂鸣属于另一业务入口，见[蜂鸣第一轮](buzzer-backlight-0041-20261023.md)的 B5；未发现它由此 GPIO callback 调用。库 timer/POSIX 接口形状可识别，但精确开源版本和厂商改动未确认，适配和业务 callback 继续在恢复范围内。
