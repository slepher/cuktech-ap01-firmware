## 本轮复核与真正新增

旧两个局部复位body再次核原字节，不算新增body。新增合同是**三个关闭触发→实际复位阶段→重新发现清槽→MiIO残余入口**的连接与先后；初始化前缀70B此前仅extent/directcall，本轮新增有限原字段用于消歧5558职责，未恢复整个初始化器。

| 输入/触发 | 关闭状态、顺序与结果 |
| --- | --- |
| ADC确认离线 | 继承有效记录/六次确认及阶段3跳过；`0xa00a4302→3d22`，`4306→3ab6`。先presence/counter清零、同步UI离线并释放快照，再释放底座缓存。没有请求完成返回或取消凭据。 |
| 普通handler事件 `0x23` | `0xa00a8836..8855`读`b50c`，等2直接返回；否则写2，再`884c→3d22`、`8850→3ab6`。后者最终把`b50c`清0，因而2不是此退出后的永久关闭闩锁。无需改动旧dispatcher的其他分支。 |
| OTA退出 `0xa00a4708` | `4710→3d22`、`4714→3ab6`；然后恢复普通handler=`0xa00a8582`、写`b4f8=2`、OTA阶段回0、`b50c=0`及`b51c=1`并撤销测试回调。沿用旧OTA合同；不是UART销毁。 |
| 上述共同`3ab6` | 三个非空动态槽`b2d0/b2d4/b6c4`依序free后置NULL；`b01c`只在首槽非空分支清。尾部`3b10`清`b51d`、`3b18`清`b50c`。**本body不清`b01d`、传输state、四槽occupied或9428.data。** free服务副作用/外部别名不在本局部负结果内。 |
| `0xa00a5558` | 继承期望`b01d=0`、control16/companion16=0、自定义首byte`b518=3`等缓存复位。既有direct_calls仅两个caller：`0xa00a55ba`前缀`55fc`，和`0xa00a805a`的`8150`。前者先清三动态指针及`b50c/b51c`再调用，是初始化形态；不是上述三关闭链的callee。间接caller仍未穷尽。 |

`805a`是既有20ms参数注册的业务LV timer，**不是**共享MiIO timer `0x62fc9428`。在phase3，`80ae/80b2`取`context+c5` presence，零跳到`826c`日常计数段；本次USB分支不调用retry/轮询/5558，也不释放四槽。timer本身继续轮转，不据此推断底层调度精度或fd已经注销。

presence非零且`b50c==0`的重新发现分支按以下原序运行（其他阶段保持原合同）：

1. `80ca..8100`分别清`b458`起0x32B、`b48c`起0x60B、`b2f0`起0x61B；最后一段含活动传输与响应区，**不含**四槽起点`b354`。
2. `8108`写`b4f8=2`，`8110`清活跃handler，`8114`再清transport state。
3. `8120`读`b51c`用于日志，`8146`再读；只有本次读为0才`8150→5558`、恢复普通handler、依次清`b354/b384/b3b4/b3e4`四个occupied byte，再submit `D1,len0,NULL`。非0跳过这组操作而继续counter路径。

这给出期望复位/四槽逻辑丢弃的**延后条件**，不能改写为离线瞬间的取消。无请求级结果、失败通知、free或取消回调随occupied清零返回；payload为固定存储，源payload早已同步复制归还。D1提交仍继承无显式入队成功结果，不能把进入重新发现分支当底座已重连成功。
