# B04：cmd0x55 后的 phase=1 局部分支

2026-10-23；基线 `77be5da`，分支 `codex/re-0041-b04`。**局部写入及前置控制流已恢复，待独立技术复核；完整响应函数仍部分恢复。** 以下是分析伪代码，不是原始源码。

## 问题与结论

响应 callback `a00a8582(command,length,payload)` 的 cmd **0x55** 路径在 `a00a8a98` 写 `62fc4b35=1`，随后在 `a00a8a9c` 清 `62fc4b37`（round_done），逐组清 `groups[i]+6`（sent），最后 `a00a8aae` 调轮询选择器 `a0191746()`。不能把次序改成先清组计数再写 phase，也不能表述成仅设置 phase。

写入有前置条件，不能表述成“收到0x55总写1”：先调用 `a0191652(62fcb004,0x18,&response_view)`；**返回之后**从缓存 `62fcb004+0x10/+0x12` 读取两个 unsigned halfword，OR 后取低16位，非零才进入本地初始化路径。为零则调用另外的状态处理路径并离开本投影，不经过此写入。条件不是 helper 返回值，也不是 response length 或原 payload 的即时读取。

该路径还有缓存/内存构建及逐项注册前奏。本任务只恢复其进入本局部的控制关系；不恢复这些操作内部语义，不把非零条件当成完整初始化成功判据。准确的紧邻入口是 `a00a8a88` 的 signed `s1 < s3` 循环已经退出：s1 从0开始，每次调用 `a01b28ce(s1)` 返回后加1；s3 是先前从 `62fcb01c` 读取的 unsigned byte 快照。因此本局部在这些前奏调用返回、循环到达退出边后才执行；**不证明运行时必定到达**。

## 前置边界与指令事实

`a00a8602/8606` 构造0x55并比较原command寄存器，等于时跳 `a00a88f6`；上游入口 `a00a85ac..85c8` 排除0x57且选择小于0x57、大于0x51的路径。两者共同确认原a0严格等于0x55，不把栈里截断的command byte反推为完整入参。

`a00a88f6..8904` 构造缓存helper参数。`a00a890c` 从缓存+2读另一个halfword，`a00a8918..892c` 用0x0a01/0x0a02映射一个独立byte；这段没有提前return，不能把这个值等于0x0a01或0x0a02追加成phase=1条件。真正控制是否继续的是 `a00a8930/8934/8938/893a/893e` 的两个halfword/OR/低16位提取/非零跳转。为零时 `a00a8940..894e` 调 `(2)` 状态处理、`(0xa,1)` 状态处理并跳 `a00a88e2` 的共同离开路径。

非零到 `a00a8950` 后先写 `62fcb50c=1`，然后缓存+0x16等于0xff时跳 `a00a8a22`，沿用旧 `62fcb01c`；其他值进入更新该byte及缓存构建的前奏。本文不恢复该前奏业务。`a00a8a22` 读取s3快照；调用 `a00a3d22()`、`a008e362(0x17c)`。后者返回零时 `a00a8a3c` **直接跳到 `a00a8a82`**，仍可执行phase写入，故“分配成功”不是该写入必要条件。非零时另有构建循环及通知调用，最终也汇入 `a00a8a82`。这些被调函数和内部构建循环的完整行为、间接副作用与运行时终止情况未在本任务验收。
