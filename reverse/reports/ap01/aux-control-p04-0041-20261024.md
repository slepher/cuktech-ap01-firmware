## 继承结论

原件沿 [CATALOG](../../../roms/CATALOG.md)：0041，`ap01-1.0.2_0041.bin`，6,769,704 B，SHA256 `972db4c136c7ed9e24a83c07c1a7fd62040ca018b08ca285216d26b1fee3c6b9`，`file_offset=VA-0x9ffff000`。未重新制作原件哈希清单。

[N01](mode-interface-n01-0041-20261024.md)及[NR01](mode-interface-review-nr01-0041-20261024.md)已验：

- `0xa00a417c(value,force)` 把 `u16(0x62fcb51e)` 与**完整32位** value 比较；不同或 force 非零才截低16位保存，提交 cmd62/len2。无需重新恢复该62B helper。
- cmd57 的6B读回缓存起于 `0x62fcb510`。首次协调阶段调用 `(10,0)`；阶段1且 mode相同、`u16(b510)!=u16(b51e)` 时调用 `(u16(b51e),1)`。这是期望半字与报告半字的协调，单位未知。
- cmd62应答先复制原1B到 `b50d`、清传输state；`u16(b516)!=100` 才写100并提交 cmd61/len2。cmd61也保存原1B。两者没有在此分支解释应答码或据其真假决定是否继续。
- `0xa00a5558` 复位两个缓存为0；关闭/迟到工作的全局先后由 P-01 独占，本题仅继承复位值。传输去重、满槽无业务结果，payload同步复制，源不转移所有权，均沿 N01/B19/B21。

`b51e` 与 `b516` 是独立字段；cmd57只覆盖 `b510..515`，不会把 `b516` 当相邻报告半字写回。不能将收到的 `b510`、期望 `b51e`、cmd61缓存 `b516` 合为一个“已应用值”。

## 真正新增：基础信息分支的固定输入

正常响应dispatch的 `0xa00a8602/8606` 将 cmd55路由至 `0xa00a88f6`。其必要顺序：

```c
// 分析伪代码，非原源码；日志/型号分类及其他分支省略。
cache_update(b004, 24, &response_view); // 固定24B；先清state，可同步回调
// 回调返回后重新从全局基础信息缓存取字段。
if ((load_u16(b014) | load_u16(b016)) == 0) {
    opaque_a00a3a58(2);
    set_control16_a00a417c(10, 1);
    opaque_a00a385a(2);              // 跳到0xa00a88e2，随后本层返回
} else {
    // 原非零路线0xa00a8950及后续初始化不在本题展开。
}
```

证据：`0xa00a8904` 调 cache helper；`8908` 构造缓存指针；`8930/8934` 各取16位，`8938` OR、`893a` 截16位、`893e` 非零跳过；`8942`→`a00a3a58`；`8946/8948` 明确 a1=1/a0=10，`894a`→真实helper；`894e`跳往原路线 `88e2`，不是直接进入非零路线。缓存对应字段的产品名仍未知，不将“两个半字均0”命名为硬件故障或错误码。

因此即使缓存已经是10，这个分支仍强制再提交 cmd62。其输入来自固定业务策略常量，不来自本分支响应payload中的任意16位参数；读回字段仅决定是否走此路径。cache helper先同步回调，故不能把两个判定值提前为进入dispatcher时的payload快照。两个opaque调用内部保持边界，不赋造恢复/告警语义。
