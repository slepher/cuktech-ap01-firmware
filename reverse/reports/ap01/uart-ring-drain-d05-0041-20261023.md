# D05：UART TX ring 消费、条件 DMA 完成与写者通知

2026-10-23；研究基线 `59d81c2176fa6b2a9ca41f8fecc35c4426b08d29`；分支 `codex/re-0041-d05`。恢复正常 TX 消费与设备副本可复用的静态闭包，**待新 agent 独立技术复核**。关键纠正是：`a001a70a(dev)` 受 private+e 门控；所核 ttyS1 private 的启动初值 +e=0，因此不能预设正常安装使用 DMA。初始配置支持的主链为 UART IRQ→逐 byte 消费→tail/通知；另恢复 +e 非零时的两段 DMA 安装、callback 与 tail 归还。

应用 `reverse-engineer-anything` skill，直接只读主仓库原 ROM，以独占脚本留存原指令；没有打开/切换共享 REA target 或可写数据库。未执行固件、连接设备或外部服务、历史回放、异常/超时/长度/漏洞审计；未改 ROM、生产代码、构建配置和分析器模型。D03 的 fd/帧/文件引用和同步 byte 复制、D04 optional_mark 纠正作为合同，实际 acquire a3=0；本轮不重做它们。

## 问题的有证据答案

1. 对 device `62fc36d0`，lower=`a01bcb18`、private=`62fc36b4`。原初始化 private 首byte=1、IRQ byte@1=0x3d、byte@d=1、byte@e=0；这只是启动复制初值，不是运行中恒定值。`a001a724` 在 +e=0 跳到返回，既不消费 ring，也不安装 DMA。
2. 首次 open 的 lower+8=`a001a1d8` 把 `a0019ae0` 与 dev 安装到 IRQ 表。公共分发把保存的 dev 读到 a2；UART callback 的 TX bit4 分支在 +e=0 时调用 `a002d36a(dev)`。初始 lower+48=0，ready+38=`a001972c` 恒返回1，故走单 byte consumer，send+30=`a0019876` 接收 scalar byte。
3. 单 byte consumer **先 halfword 发布 tail+1，再读 ring[旧tail]，再调用 lower send**，最后按 signed capacity 回绕；有进度后调用 `a002be92(dev)`，空环先重读 head/tail 才关闭 TX interrupt。软件把该槽视为已消费不等于 UART 线上的字节发送完毕，更不等于对端收到。
4. +e 非零的条件路径中，`a001a240` 确切安装 `a0019d9a(dev)` 到 DMA callback 表。两段传输的 callback 通过剩余计数和 phase 判定是否结束；结束时累计 dev+88，调用 `a002d5d8`。后者在 descriptor first pointer 与 ring+tail 相等时按 unsigned remainder 推进 tail；随后无论 pointer 是否匹配均按 +88→+84→+80 顺序清零，非零累计数才通知。此 callback 的代码身份与安装已定位，硬件何时触发并未观测。
5. `a002be92` 先通知 poll 槽，再处理 dev+18 的 semaphore 等待者。等待 write 的 `a002c140` 已在 mask8 临界区内重查满环、启动 lower、enable TX、wait(dev+18)，返回后 disable TX、恢复旧 mstatus，再循环重查 tail；唤醒不是预先承诺一定可放 byte。同步调度器内部保证与 DMA 底层 descriptor 算法保留明确边界。

## 初值、安装及真实 IRQ 消费

RAM 初值使用既有启动复制合同 `ROM a00027d4→RAM62fc2cc0`；dev 映射 ROM `a00031e4`，private 映射 ROM `a00031c8`。本轮实际读原byte验证 private+e=0。lower 表原 word：+8=a001a1d8、+20=a001a240、+2c=a001a70a、+30=a0019876、+34=a0019810、+38=a001972c、+48=0。dev+58 ring=`62fc78a8`、+a0/+a4如上；容量 signed16@54=0x400、head/tail初值0沿用D04。

首次 open 在dev open_count从0→1的正常分支，mask8下 `a002bae6` 读 lower+8、`bae8 c.jalr a5`。`a001a1e8`令a2=dev，`a1ea/f2`构成a1=a0019ae0，a0=private+1的u8 IRQ，经`a1f6`调用a0026498。installer对IRQ上界0x5f作signed比较，mask8下把callback写到 `62fc662c+8*irq`，arg写+4；恢复旧mstatus并返0。attach非零返回直接保留结果，零才以IRQ调用a001a020。open相关的引用和其他初始化沿用D04。

公共分发 `a000101a` indexed load callback；`1026`将同槽arg读到a2；在一次日志调用后从栈恢复a2，`1042/44`令a1=context、a0=IRQ，`1046 c.jalr s2`。因此不是仅靠字符串或相似函数名断言a0019ae0接收dev。

type≤1的 UART callback：从 `private+10→word+4` 的寄存器基址取status@20和mask@24，`a0019b1e..22`计算 `active=status & ~mask`；bit4非零且private+e=0才`9b34→a002d36a(dev)`；回来重读寄存器基址并OR4写mask@24。相邻RX位及另一型号的实现均不作为本轮恢复结果。另一型号TX短切片 `9c4e..6b` 保留 +e==0调用同一consumer，硬件表查询内部留边界。

```c
// a002d36a，16位读之后显式 sign16；每次 L 表示重新读内存。
void drain_irq(Dev *d) {
    uint16_t progress=0;
again:
    if (sx16(L16(d+0x50)) != sx16(L16(d+0x52))) {
        if (!L32(L32(d+0xa0)+0x38)(d)) goto finish;
        ops=L32(d+0xa0); ring=L32(d+0x58); bulk=L32(ops+0x48);
        if (bulk==NULL) {                     // 当前安装走这里
            send=L32(ops+0x30);
            raw_tail=L16(d+0x52); old=sx16(raw_tail);
            progress=(uint16_t)(progress+1);
            S16(d+0x52, sx16(raw_tail+1));     // 原码在 byte load/send 之前
            byte=U8(ring+old);
            send(d,byte);
        } else {
            t=sx16(L16(d+0x52)); h=sx16(L16(d+0x50));
            if (t<h) count=sx16(L16(d+0x50))-sx16(L16(d+0x52));
            else count=L_i16(d+0x54)-sx16(L16(d+0x52));
            ptr=ring+sx16(L16(d+0x52));
            result=bulk(d,ptr,count); if (result<=0) goto wrap;
            raw_tail=L16(d+0x52); accepted=(uint16_t)result;
            progress=(uint16_t)(progress+accepted);
            S16(d+0x52,sx16(raw_tail+accepted));
        }
wrap:
        if (sx16(L16(d+0x52)) >= L_i16(d+0x54)) S16(d+0x52,0);
        goto again;
    }
finish:
    // 原码重读 head/tail；不复用进入finish之前的值。
    if (sx16(L16(d+0x50)) == sx16(L16(d+0x52)))
        L32(L32(d+0xa0)+0x34)(d,0);
    if (progress!=0) notify_writers(d);
}
```

bulk返回≤0仍到wrap再循环，未被改写成提前退出；不对此分支做输入/失败实验。当前+48=0，bulk指针寿命和动态安装者仅为未启用的接口边界。progress每次经 `th.extu ...,15,0` 截16位，不能改成无界累计值。正常ready恒1的当前scalar路径每轮重读head/tail，能消费写者在此期间发布的新byte；这不是并发模型/公平性证明。

原指令定位：`d37a..d39e`两次head/tail读与sign16；`d3e6:2399f404` halfword写tail，`d3ea:8bc5d580` unsigned indexed byte load，`d3ee:0297` indirect send；`d458..d468` signed比较capacity并halfword清tail；`d3b4`原JAL到a002be92。lower send内部按值合同沿用D04，不能用“ready”恒1推断硬件实际空闲或线速完成。

## 条件 DMA：分段、重启和确切 callback

`a001a70a`第一门private+e非零，channel byte来自 `gp+3dc+type` 并sign8。channel不在0..2时 `a001a8ee→a00288de`取得并byte发布；重读若仍负到断言边。本轮没有展开全DMA channel allocator。合法channel调用 `a0024bec`读 `handle->regs+10 &1`，若活动则先在 `2000c110+channel*0x100` OR0x40000，调用stop `a0024bb6`、clear `a0024c20`，再清相同0x40000位；从 `2000c10c+channel*0x100` 取低12位remain。

活动记账：type≤1的first_len来自 `62fc86d0[typ]`，second_len来自 `62fc86d8[typ]`，phase byte在 `62fc86e0[typ]`；phase=0时consumed=first_len-remain，phase非0时consumed=first_len+second_len-remain。type>1对应单独word `62fc85f0/5f4`与byte `62fc85f8`。先清phase，再在consumed非0时word写dev+88并调用release。由原MMIO计数和数组算软件进度，没有认证字节已经离开UART外设。

随后再次按sign8重读channel，合法且ring非空才准备descriptor；所有head/tail是halfword读→sign16，没有把首次snapshot复用到后续计算。

`a001a240`把ROM `a01bb000` 的20B模板复制到自己的栈配置，将 dev+78/+80 与 dev+7c/+84复制为两个各12B栈描述项 `{src,dst,count}`；两项dst在type0为2000a088，type1为2000a188（type1另将配置+8设3），type2通过a066e000相对操作表+28/+24查询。n1=0或channel不合法时返回，不伪造成功计数。它先清dev+88，清pending，再将first_len/second_len保存到上述持久数组并清phase；type≤1另置UART寄存器+80 bit0；随后configure、txint(dev,0)、安装callback、clear/mask、submit、enable。

**确切安装证据**：`a001a3f6 b7a501a0` 与`a3fc 9385a5d9`构成a1=`a0019d9a`；`a3fa` a2=dev，a0是 `62fc603c[channel]` handle，`a400` JAL到a00264ec。该函数读handle+9的group和+a的channel，`64fc`算index=channel+4*group，`6500`把callback写 `62fc5c4c+8*index`；再次重读group/channel，`6514`写arg到同槽+4。不是从名字推测 callback。

group0时安装者将 `a0024b12` 写临时IRQ pair并以handle+8+0x10调用a0026498，然后enable相应IRQ；其余group的中断安装保持原返回边界。DMA公共IRQ `a0024b28`读2000c004，`4b34`先把pending写2000c008清除，再扫描8槽；有位时读callback及arg，`4b4a`令a0=arg，`4b4c c.jalr a5`。因而同一callback接收的是单参数dev，区别于UART IRQ的三参数ABI。

提交以type≤1的 `62fc86e4+64*type`（type2为62fc85fc）为持久descriptor存储参数，n2=0则a3=1，否则a3=2，a2指向本地两项描述数组。`a01a47dc` wrapper选handle->4并改排参数，再调 `a01b554e(regs,storage,4,stack_desc,number)`；之后 `a0024b7e`置channel regs+10 bit0。本轮不恢复a01b554e整套descriptor构建/地址转换/缓存处理算法；只确认真实参数与直接目标，不能认证这层对栈描述数组的深拷贝性质。ring byte和dev/phase/长度均持久存在，源frame在D04已同步复制，不因该栈描述边界重新变成DMA借用原frame。

### 正常完成与 tail 归还

type≤1 callback首先读持久second_len：为0直接终结；非0且phase!=0也终结；phase=0且channel寄存器低12位为0直接终结，否则clear pending→phase=1→重读remain，若重读为0当次继续终结，否则返回。type2同一流程使用其单独state。没有把phase1设置本身误当整个两段已完成，也没有以callback调用次数代替该判断。

终结先stop(channel)→clear(channel)→phase=0；先word写dev+88=first_len，再重读second_len、相加后**第二次**word写dev+88，最后 `a0019e2c→a002d5d8(dev)`；不要把两个state发布合并成单一赋值。

```c
// a002d5d8；U32/remu和写宽按原码。
void release_dma(Dev *d) {
    old_tail=sx16(L16(d+0x52)); consumed=L32(d+0x88);
    expected=L32(d+0x58)+old_tail; first_ptr=L32(d+0x78);
    if (first_ptr == expected) {
        t=sx16(L16(d+0x52)); cap=L_i16(d+0x54);
        // RV32 ADD、REMU：cap作为32位unsigned除数；再sign16并SH。
        next=(uint32_t)(t+consumed) % (uint32_t)cap;
        S16(d+0x52,sx16(next));
    }
    S32(d+0x88,0); S32(d+0x84,0); S32(d+0x80,0);
    if (consumed!=0) notify_writers(d);
}
```

`d5ea:631ff700` mismatch跳到d608，仍清三计数并可通知；不能声称该门的失败路径推进tail。此函数不写head、不清p1/p2、不自动再次启动lower。scalar消费者也只写tail；head由已验收enqueue在byte复制后发布。所谓“忙”是channel寄存器enable bit、phase及descriptor长度等多处state，没有证据支持凭dev+88构造一个统一busy bool。

## 唤醒、等待与所有权

dev分析布局：head:i16@50、tail:i16@52、capacity:i16@54、ring:ptr32@58；DMA p1/p2:ptr32@78/7c，n1/n2:u32@80/84，consumed:u32@88；lower:ptr32@a0、private:ptr32@a4；write锁@40、write等待对象@18；poll slots由dev+ac起。private type:u8@0、IRQ:u8@1、TX DMA gate:u8@e。类型名均为解释；+d是本闭包相邻RX条件字，不重解其业务。

`a002be92`按原序：`a3=4,a2=4,a1=0,a0=dev→a002bcec`，随后a0=dev+18→a002b8de。poll notifier在mask8下，必要时进入调度临界helper，再将 first+0x2b乘4加dev交 `a002e2a0(pointer-to-first-slot,count,event)`；本次count4，event4。之后退出调度helper并恢复mstatus。poll core是否持有slot及其所有用户另列边界，不展开订阅系统。

waiter helper读取 semaphore 起始halfword并sign16到局部count；局部count>0即返回，否则调用a00273cc(semaphore)一次，局部count+1，循环直到>0。原码不是每次重读semaphore count，本轮保留这个差别。a00273cc是post边界（静态短读核到mask8、signed16 count+1、必要等待链唤醒），完整调度返回时机不在本轮范围。

writer满环可等待路径在mask8下再次比next和tail，仍满时按 lower+2c(dev)→lower+34(dev,1)→wait(dev+18)→lower+34(dev,0)→恢复旧mstatus 顺序执行；wait结果非负回到tail重查，负则原返回-4。允许重复唤醒/重查，没有把通知改成任意数量byte的预留。不可等原分支返-11。写者的dev+40锁与consumer局部中断控制不是同一锁，未声称跨核原子或顺序保证。

生命周期：应用frame的byte值先由D04复制到静态设备ring；write返回的源已接受部分无需借到IRQ或DMA完成。scalar normal消费把tail发布后向lower传标量；设备槽的逻辑复用与物理完成分开。条件DMA使用设备ring中的ptr/count，两段state存在设备/全局数组；release推进tail并清长度才形成设备副本逻辑归还。没有free ring/frame/dev的指令，不发明堆分配所有权；fd局部引用release并不取消设备传输。本轮没有证明DMA底层对stack_desc的最终保留合同。
