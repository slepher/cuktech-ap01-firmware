# 将外部程序打包进 AP01 ROM

本说明面向希望在 AP01 原厂系统中嵌入自有程序的外部项目。这里的“接入”指编译、链接、注入并重建完整 ROM 更新包；不要求使用某个桌面产品、网络协议、模板引擎或绑定流程。

## 1. 输入与版本

先按[镜像清单](../../../roms/CATALOG.md)核对原件长度和 SHA256。0031、0041 的函数地址、资源位置、补丁范围和更新限制分别维护，禁止混用。更新包文件偏移、运行 VA 和物理 Flash 地址分别处理；0031 的常用映射为 `VA = 文件偏移 + 0x9ffff000`，不适用于任意区域或物理写入。

准备精确原件、外部程序源码、RISC-V 工具链及明确的链接布局。现有脚本是特定实验的构建器，不能将任意 ELF 直接替换为固件。原件不覆盖，构建产物写入独立目录，清单记录全部输入和输出哈希。

## 2. 编译与链接

[模块源码](../../../tooling/firmware-modules/README.md)和[构建工具](../../../tooling/scripts/README.md)提供可复查的最小参考：

| 参考 | 用途与限制 |
| --- | --- |
| `build_app_rom.py`、`entry.S`、`base.ld`、`app.ld` | 0031 同步 native-XIP 诊断程序，证明受限调用流程；不是长期运行的通用应用宿主 |
| `app_abi.h`、`app_loader.c` | APX1 版本化 ABI、长度和入口检查、状态初始化；CRC 和基线摘要不提供发布者认证 |
| `build-ota-channel-0031.sh/.py`、`ota_0031.ld` | 指定地址链接的 0031 独立 OTA 实验模块及 ROM 打包参考 |
| `build-ota-channel-0041.sh/.py`、`ota_0041.ld` | 基于冻结 0041 unsigned 候选的离线实验，不能据此推导实机可安装 |
| `build-ota-expanded-0031.py` | 0031 扩容及槽尾布局实验，具体候选按各自记录判定 |

现有载荷使用 RV32 交叉编译；ISA、ABI 和编译选项以对应构建脚本为准。原厂含厂商扩展指令，不应把未知编码按其他 ISA 猜测执行。复用原厂调用前核对参数、返回值、调用约定、上下文及生命周期；保留原厂 SP、GP 和被调用者保存寄存器。

链接必须明确代码、只读数据、初始化数据、BSS、状态区和栈。历史载荷链接脚本只容纳代码及常量，不能直接放入依赖可写全局、C++ 构造器或完整运行库的程序。现有同步 ABI 禁止线程、异步回调及返回后保留服务表/栈指针；长期程序需要另外验证任务创建、停止、资源释放及缓存同步。

## 3. 注入位置与资源约束

0031 历史 XIP 实验通过无损压缩原厂 GIF 腾出文件区间 `[0x2475d0, 0x2563d6)`，共 60,934 B；这不是原件的空闲字节，也不是任意可用的槽尾。外部程序必须按实际代码、常量及资源尺寸检查容量和跳转范围，不能仅凭同名镜像或旧地址复用布局。

0031 静态证据显示两个 7 MiB 固件槽、64 KiB `/data`、1.25 MiB `/resource`，并将 4 MiB 外部内存加入通用堆。它们是配置证据，实际剩余空间、最大连续块和任务余栈须测量。不得把备用固件槽当作普通文件仓库。

320×240 单色帧为 9,600 B，RGB565 单帧为 153,600 B；预算还要包括原厂 UI、网络、字体、解码器、任务栈、临时缓冲和更新峰值。冻结的历史业务尺寸探针仅对应当时输入，不能当作任意外部程序的预算。

## 4. ROM 重建与验证

1. 从精确原件构建新候选，只修改清单声明的入口、载荷、资源和必要元数据。
2. 核对链接 map、段地址、未解析符号、重定位、入口范围、可写状态和栈预算。
3. 重建相应容器的长度、头部、CRC 和尾记录，使用原件校验器检查允许修改范围；修复 CRC 不等于通过厂商验签。
4. 保留原厂启动链、GIF/资源、PEC、分区与传统 OTA 入口，除非该实验明确研究其中某项。逐字节比较保护范围。
5. 先做宿主检查、受限执行及 QEMU 验证；OTA 实验须独立核对提交后的 NOR，再以同一 NOR 快照虚拟复启。模拟不替代实机启动、原厂功能与恢复验证。

0031 XIP 的实现及历史构建结果见[实现验收](app-implementation-20261013.md)，OTA 构建和检查入口见[工具说明](../../../tooling/scripts/README.md)。本文不提供“替换任意程序即可刷入”的通用命令；外部项目应根据这些参考提供自己的受限构建入口和清单。

## 5. 安装与执行边界

首次交付、当前系统的更新校验和 Boot ROM/Boot2 启动校验是不同阶段。0041 的 unsigned 拒绝离线补丁不证明实机启动链接受修改镜像。0031 已记录的实机候选也不保证其他程序、地址或扩容布局可用。

将程序静态打包进完整 ROM 与运行时下载/装载程序是两条路线。前者随完整镜像更新；后者还须验证可执行内存、重定位、初始化、任务退出及启动恢复，现有 APX1 同步原型不证明这些能力。OTA 独立任务也不等于进程内存隔离或可靠回滚。

外部项目引用本说明及对应实验报告，维护自己的业务代码、依赖、资源上限和发布验收。这里持续维护可复查的固件事实与打包约束。
